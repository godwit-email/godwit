# 发版前真机核对清单

后端进程拆分（[ADR 0038](adr/0038-backend-process-owns-the-engine.md)，#714）之后，有些行为只有签名的安装包装在真机上才看得到，CI 测不到。每次发版前，在 macOS 和 Windows 上各走一遍；有 Linux 桌面的话也走一遍 Linux 这一节。每条写了怎么查、怎样算通过。走查中发现的问题各开一个 issue，并在发版 PR 里列出来。

准备：

- 用正式签名的安装包：macOS 用带 provisioning profile 的 Developer ID 版 `.dmg`，Windows 用安装程序和 MSIX 两种。
- 准备一个能收信的测试账户，再准备一个能给它发信的邮箱。
- 查进程：macOS `pgrep -lf godwit`；Windows 任务管理器「详细信息」或 `Get-Process Godwit`；Linux `pgrep -af godwit`。后端的命令行带 `--headless`，界面进程不带。

## 安装、升级、卸载（macOS、Windows 安装程序、Windows MSIX 各走一遍）

- [ ] **全新安装**：在没有装过 Godwit 的用户下安装并打开，添加测试账户。通过：窗口打开，能收信；进程里有一个后端和一个界面。
- [ ] **从上一个版本升级**：先装上一个正式版，添加账户，后台收信选「一直继续」，关掉窗口，让后端留着运行；再装新版本并打开。通过：界面启动的旧后端被换成新版本的后端（`--version` 或「关于」里的版本对得上）；收信、通知照常；后台收信仍是「一直继续」，登录项仍在。
- [ ] **升级时用户自己启动的后端**：用 `godwit --headless` 手动起一个旧版本后端，再打开新版本的界面。通过：这个后端不被停掉，界面告诉用户它版本不对、需要自己重启它。
- [ ] **升级不丢、不重发发件箱**：升级前断网，写一封信点发送，让它留在发件箱；升级后联网。通过：这封信只发出一次，发件箱清空，收件方只收到一封。
- [ ] **卸载**：在「一直继续」、后端正在运行时卸载（macOS 把 `Godwit.app` 拖进废纸篓；Windows 在「设置 › 应用」里卸载）。通过：卸载后没有 Godwit 后端进程；macOS「系统设置 › 通用 › 登录项」和 Windows 任务管理器「启动应用」里都没有 Godwit；注销再登录也没有 Godwit 启动。

## macOS

通知与权限：

- [ ] **通知授权只问一次**：全新安装后第一次需要通知时。通过：只弹一次通知授权；「系统设置 › 通知」里只有一个 Godwit，名字和图标是 Godwit 的，没有第二个条目或无图标的条目。
- [ ] **后端发的通知带发件人头像**：关掉窗口，用另一个邮箱给测试账户发信。通过：通知由后端发出，左侧是发件人头像（communication 通知），标题是 Godwit。
- [ ] **验证码横幅**：关掉窗口，给测试账户发一封带登录验证码的信。通过：后端弹出验证码通知，可以复制验证码。
- [ ] **后端不出现在 Dock 和 ⌘Tab**：关掉窗口只留后端。通过：Dock 和应用切换器里都没有 Godwit。

登录项（`SMAppService`）：

- [ ] **首次登记**：后台收信选「一直继续」。通过：系统提示有新的登录项（第一次需要用户允许）；「系统设置 › 通用 › 登录项」里出现 Godwit。
- [ ] **登录只起后端和托盘**：保持「一直继续」，注销再登录。通过：后端和菜单栏图标起来，不开窗口（Dock 图标可能闪一下，可以接受）；关窗前收到的新信照常通知。
- [ ] **在系统设置里关掉登录项**：在「系统设置 › 通用 › 登录项」关掉 Godwit，再打开 Godwit 的设置。通过：后台收信下面显示「系统设置里已关闭 Godwit 的登录启动；请在那里重新开启」；再注销登录，Godwit 不启动。

界面与后端：

- [ ] **点通知唤起界面并显示到最前**：没有界面进程时点一条新邮件通知。通过：界面启动，窗口到最前面（界面是直接 exec 起来的，重点看它不被压在别的窗口后面），打开的就是这封信。
- [ ] **自定义数据目录下连点两次**：用 `--data-dir` 指向一个测试目录跑后端，没有界面时快速点两次通知。通过：最终只剩一个界面窗口（目前可能先起两个界面；若第二个没有把请求交给第一个并退出，开 issue）。

## Windows（安装程序和 MSIX 都走）

- [ ] **原生通知**：关掉窗口，给测试账户发信。通过：右下角弹出通知，名字和图标是 Godwit；「设置 › 系统 › 通知」里只有一个 Godwit 条目；点通知打开这封信。
- [ ] **验证码横幅**：关掉窗口，发一封带验证码的信。通过：后端弹出验证码通知。
- [ ] **托盘**：关掉窗口后托盘图标还在。通过：「打开 Godwit」打开窗口；写信入口打开写信窗口；「退出并停止收信」退出后没有 Godwit 进程。
- [ ] **MSIX 登录启动（`StartupTask`）**：后台收信选「一直继续」，再关回别的模式。通过：任务管理器「启动应用」里 Godwit 随之变成「已启用」/「已禁用」；选「一直继续」时注销登录后只有后端和托盘、没有窗口。这段 WinRT 代码从没在真机上跑过，出任何错都开 issue。
- [ ] **MSIX 在任务管理器里被禁用**：在任务管理器「启动应用」禁用 Godwit，再打开 Godwit 设置。通过：后台收信下面显示登录启动已在系统里关闭的提示。
- [ ] **安装程序版的 Run 键**：非 MSIX 版选「一直继续」。通过：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里有指向 `Godwit.exe` 的一项；关回别的模式后这一项消失；注销登录后只起后端和托盘。

## Linux

- [ ] **后端常驻并发通知**：打开 Godwit，后台收信选「关窗后继续，退出即停止」，关窗后发信。通过：桌面通知弹出，名字是 Godwit；托盘（有托盘的桌面上）还在。
- [ ] **验证码横幅**：同上，发一封带验证码的信。通过：弹出验证码通知。
- [ ] **systemd 用户服务**：按 README「Receive mail from login on Linux」写好 `godwit.service` 并 `systemctl --user enable --now godwit`，然后打开桌面应用。通过：界面连上这个后端；退出界面后 `systemctl --user status godwit` 仍是 active；重新登录后后端自己起来并发通知。

## 所有平台

后端生命周期：

- [ ] **界面启动并连上后端**：没有后端时打开 Godwit。通过：起一个 `--headless` 后端，界面连上它，收信正常。
- [ ] **退出只停界面起的后端**：分别用界面起的后端和手动 `godwit --headless` 起的后端，各点一次「退出」。通过：前者后端退出；后者后端留着。
- [ ] **后端崩溃**：界面开着时杀掉后端进程（`kill -9` / 任务管理器结束任务）。通过：界面显示「Godwit 的后台进程意外退出。再次打开 Godwit 即可重新启动它。」；再打开 Godwit 时后端重新起来。
- [ ] **启动出错的对话框**：已有一个 Godwit 在用这个数据目录时，用另一个可执行文件或另一个用户的身份打开同一目录；把数据目录设成不可读。通过：分别弹出「Godwit 已在运行」和「Godwit 无法打开数据目录」的对话框，而不是静默退出。

关窗与后台收信（三种模式各试关窗和退出）：

- [ ] **关窗后停止**：关窗后。通过：界面和后端都退出，没有 Godwit 进程，不再通知。
- [ ] **关窗后继续，退出即停止**：关窗后界面先隐藏、后端留着并通知；在托盘点「退出」后所有 Godwit 进程退出。
- [ ] **一直继续**：关窗和「退出」后后端都留着并通知；托盘上有「退出并停止收信」，点它后后端也退出。
- [ ] **关窗先隐藏，5 分钟后退出界面进程**：在后两种模式下关窗。通过：5 分钟内从托盘、Dock 或点通知重开，窗口立即出现，界面进程还是同一个（PID 不变）；隐藏满 5 分钟后，不带 `--headless` 的界面进程和 WebView 子进程都退出，后端留着并通知；这时开着撰写窗口的话，界面等最后一个撰写窗口关掉才退出。

MCP 发送确认：

- [ ] **没有界面时的 MCP 发送**：「通过 MCP 发送」设为需要确认，关掉窗口，让 AI 工具通过 `godwit mcp` 发一封信。通过：弹出通知，只提示有待确认的发送，不含收件人、主题、正文等邮件内容；点它打开界面并显示确认卡片，卡片上列出收件人；确认前信不发出。
