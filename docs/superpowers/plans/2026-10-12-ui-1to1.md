# UI 1:1 (visual) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every screen that exists today looks 1:1 like its design artboard. New features ship in separate plans (see "Feature plans").

**Architecture:** Work is screenshot-driven. Each task changes one area, renders the app's screens and the matching artboards, and iterates until they match. The task report attaches the before and after PNG paths.

## How to compare (every task)

**Design renders.** Design PNGs are in `$D/dshots/<Artboard>.png`:
- 1440×900 for full screens;
- 860×720 for Compose*.

To re-render one, run `python3 -m http.server 8765` in `$D/design-v2/project`, then:

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --window-size=W,H --virtual-time-budget=4000 --screenshot=out.png http://127.0.0.1:8765/<Artboard>.dc.html
```

**Native app shots.** Run:

```
GODWIT_SHOTS=$D/ashots go test ./app -run TestShots -count=1
```

This writes `$D/ashots/<Artboard>.png`. The data matches the design; see `app/shots_test.go`.

**Web app shots.** Run `cd web && bunx vite --port 5181`, then take the same headless Chrome screenshot of `http://localhost:5181/preview.html?page=<compose|wit|signature>&state=<…>`:
- compose: window 860×676 (the native title bar is 44);
- wit: 1128×848 (the content area).

The states are listed in `web/src/preview/README.md`.

**Acceptance.** Compare the screenshots region by region (crop with PIL, which is installed for python3). The task is done when:
- the layout, sizes, spacing, type, colours and copy match within 1–2 px;
- the only differences left are content that comes from data, or features that are out of scope.

The report lists the before/after PNG paths per screen and any residual difference with a reason.

### Task 1a: Line heights (the new baseline)

**Files:** `internal/theme/theme.go`, `app/shell.go`, `app/sizes_test.go`, kit, and every leaf `FontSize` call site.

1. Add the per-size line heights from tokens.json:
   - xs 1.4, sm 1.45, base 1.5, body 1.6, lg 1.5, title 1.4, xl 1.35, 2xl 1.3, display 1.25;
   - `theme.Line(size) float32`;
   - a kit helper that sets size and line height together on a **leaf** text. A line height inherits as a multiplier, so never set it on a container.
2. In `App.View`, set `c.Root().LineHeight(theme.Line(Body))`. It must go on `c.Root()`, because overlays (menus, dialogs, Select lists, tooltips, toasts) attach there.
3. **Calibrate first.** Apply only the root value, shoot Main and SettingsGeneral, and measure the list and settings row pitch against `$D/dshots`. Where tokens and pixels disagree by more than 2 px, record the choice in the audit. Pixels decide.
4. Convert the leaf `FontSize` sites. Reading bodies, summaries, translations and the drafts-pane body use 1.75 with paragraph gap 10.
5. Text inside fixed-height boxes uses `LineHeight(1)` (or FixedLineHeight): `kit.Kbd`, `capChip`, toolbar labels, the `Height(Space(5))` row in settings_models_view. Add a test that text fits its fixed-height parent at font 16.
6. Add `LineHeight` to the `sizeCall` regex in `app/sizes_test.go`, and fix the literal multipliers in `onboarding.go` (430, 438, 626, 698).
7. **Verify:**
   - Re-shoot every artboard, including the overlays (AddAccountSheet, SettingsModelsSheet, Toasts) and a Select popup.
   - `TestSettingsNoClip` and `TestReaderToolbarAt16` at 13 and 16.
