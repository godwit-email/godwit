# Godwit AI 与 Wit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 core 里加上 AI：设置、模型服务管理、Genkit 运行时、Skill 加载与内置 skill、即时回复、Wit（邮箱级 `Ask` 与撰写页 `Assist`）、持久化且只执行一次的审批，以及权限网关的最小版本。完成后不需要 GUI，就能通过 Go 测试对本地假模型服务器跑通总结、翻译、即时回复、Wit 搜索邮件并起草、撰写页改写草稿，以及审批在重启后继续。

**Architecture:** 新包 `core/ai` 封装 Genkit，对外只暴露自己的类型；Genkit 的对话状态以不透明的字节串交给调用方保存（spec 6.3 第 5 条）。新包 `core/gateway` 是权限网关：每次运行一个来源范围（是否读过邮件）、所有工具统一包装、审计。Skill 解析在 `core/skills`。`core.Service` 负责组装邮件上下文、执行获批的工具、持久化运行 / 对话 / 审批。没有可用模型服务时所有 AI 入口返回 `ErrAINotConfigured`（AI 默认关闭）。

**Tech Stack:** 计划 1、2 的全部依赖；新增 `github.com/firebase/genkit/go v1.13.1`（插件 `plugins/compat_oai`、`plugins/anthropic`），版本锁定。YAML frontmatter 用 Genkit 已经引入的 `github.com/goccy/go-yaml`。

**Spec:** `docs/superpowers/specs/2026-10-08-godwit-design.md`（重点：第 4 节 Settings / Models / AI / Extensions API、5.1–5.2 Skill、5.5 权限网关与审批、6.1 模型服务、6.3 Genkit 落地要求、7.2 总结 / 翻译 / 即时回复、7.3 撰写与 Wit、7.4 Wit、7.6 语言设置）

**基线:** 从 `feat/account-onboarding`（计划 2，PR godwit-email/godwit#2）拉出 `feat/ai-wit`；前序 PR 合并后改基于 `main`。

### 规格解释（本计划采用，已与 spec 对齐）

- **撰写页第一次生成直接写入**（spec 7.3）与「写操作一律需要审批」（spec 5.5）的关系：草稿可编辑部分为空时，第一次生成直接写入（这是用户在自己的撰写页里发起的、不覆盖任何内容、可撤销、发送始终由用户点击）；其余所有对草稿的修改都是待确认提案。这一条只适用于 `Assist` 对**当前草稿**的写入；`Ask` 的 `create_draft` 等其他写操作照常审批。
- **逐处接受修订**（spec 7.3）：core 给出旧 / 新可编辑 HTML；逐词 diff 与逐处取舍在 GUI（计划 5）里基于富文本模型完成，GUI 把用户最终确认的 HTML 交回 core 应用（core 校验版本并清洗）。core 不做 HTML 逐词 diff。
- **附件上下文**（spec 7.4）：v1 只把附件的文件名、类型和大小交给模型，不读取附件内容。

## Global Constraints

- 计划 1、2 的 Global Constraints 全部继续有效（Go 1.27.1、module `github.com/godwit-email/godwit`、不用 cgo、mygo sqlite Go API 单语句、迁移只追加、外键、只暴露 int64 ID、凭据只进系统钥匙串且不进日志 / 错误 / 事件）。
- Genkit 锁定 `v1.13.1`；Genkit 的类型只能出现在 `core/ai` 包内部。对话状态以 `[]byte`（Genkit 消息的 JSON）交给 Service 保存，Service 不解析它；展示用的消息是 `core/ai` 自己的类型。
- **Genkit 实例生命周期**：每个模型服务的每个配置版本一个 Genkit 实例（懒创建、缓存；服务修改或删除时取消它的 context 并丢弃）。`genkit.Init` 一律传入可取消的 context（让 `signal.NotifyContext` 随之退出）和 `genkit.WithPromptFS(空 fstest.MapFS)`（不加载工作目录的 `prompts/`）。模型按需 `DefineModel` 到该实例；工具**不注册**，每次运行用 `ai.NewTool` 作为动态工具传入（Genkit 把动态工具注册进一次性的子注册表）。`GENKIT_ENV=dev` 时 `ai` 拒绝初始化并返回错误（不启动 reflection 服务）。
- **环境隔离**：构造插件时总是显式设置 `APIKey` 和 `BaseURL`；Anthropic 插件另外通过 `Opts` 删除 SDK 从环境继承的认证（`ANTHROPIC_AUTH_TOKEN` 产生的 `Authorization` 头）。Anthropic 兼容服务的 API key 可以为空（本地网关）：此时传占位值 `"godwit-no-key"`，并删除 `x-api-key` 头。测试同时设置 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`，断言假服务器收到的请求头里没有这些值。
- **不导出遥测、不记录负载**：不配置任何 trace exporter；Genkit 的 slog 日志级别设为 `Error`，并经过按值脱敏的 handler（收集所有模型 API key 的值，输出前替换为 `[redacted]`，spec 5.5）；core 自己从不记录提示词、邮件内容或模型输出。
- 模型服务的 API key 存钥匙串，条目 `<install-id>/model:<service-id>`；编辑时留空保持原值。模型引用写作 `服务名/模型 ID`（第一个 `/` 之前是服务名）。
- **所有来自邮件的字段**（主题、发件人、摘要、正文、附件名）交给模型时都经过同一个上下文构造函数，放进不可信数据块，并带来源与疑似注入标记。
- **审批**：绑定运行 ID、调用 ID、**规范化后的最终参数快照**和目标版本（草稿用 `revision`）；执行只使用快照；本地写操作与「审批变为 done」在同一个事务里完成。获批后由宿主执行，再用 `Respond` + `WithToolResponses` 交还 Genkit，不用 `Restart`。
- **任何 AI 都不能发信**：没有 send 工具，工具实现里也不调用 `Send`。
- Skill 运行时没有工具、不能联网、不执行 `scripts/`（spec 5.1–5.2）。
- 所有新的公开方法（包括流式运行和审批后的续写）都经 `s.begin` 登记，`Close` 取消并等待它们。
- 测试全部对本地假模型服务器运行，不访问外网。

## Review Focus

1. **长邮件与长会话**：几 MB 的邮件或 50 封的会话交给总结 / Wit 时按字符预算截断并注明「已截断」；对话历史有总预算，工具请求与结果成对省略。→ Task 7、Task 10。
2. **重启后的审批**：待审批时退出，重启后卡片仍在，批准后只执行一次；任何时刻崩溃都不会重复创建草稿或重复续写。→ Task 9。
3. **中途断开、取消或没人读事件**：草稿不被写入半截内容，审批不悬空，运行不因消费者停止读取而挂住。→ Task 3、Task 9、Task 11。
4. **邮件里的 prompt 注入**：主题、发件人、摘要或正文里的「忽略之前的指令……」不能让 Wit 绕过审批，来源被标为疑似注入。→ Task 6、Task 10。
5. **服务名 / 模型 ID 的边界**：模型 ID 含 `/`；服务被删除或改名后，引用旧名的默认模型与 skill 覆盖给出明确错误；缓存不跨服务配置复用。→ Task 2、Task 7。

**Files:**
- Create: `core/ai/types.go`, `core/ai/runtime.go`, `core/ai/redact.go`

**Interfaces:**
- Produces（`core/ai` 对外类型）：
  - `type Message struct { Role string; Text string; Calls []ToolCall; Results []ToolResult }`（只用于展示，不用于恢复）
  - `type ToolCall struct { ID, Name string; Args json.RawMessage }`；`type ToolResult struct { CallID, Name string; Output json.RawMessage; Error string }`
  - `type ToolSpec struct { Name, Description string; Schema map[string]any; Strict, NeedsApproval bool; Run func(ctx context.Context, args json.RawMessage) (any, error) }`；`NeedsApproval` 的工具不调用 `Run`，直接中断
  - 错误码 `type Code string`：`canceled`、`unauthorized`、`rate_limited`、`unavailable`、`bad_response`、`internal`；`type Error struct { Code Code; Msg string }` 实现 `error`，并让 `errors.Is(err, context.Canceled)` 对 `canceled` 成立；`Msg` 不含 key、请求或响应正文
  - `type Event struct { Kind string; Text string; Call *ToolCall; Result *ToolResult; Interrupts []ToolCall; Err *Error }`；`Kind` ∈ `text`、`tool_call`、`tool_result`、`interrupted`（本轮全部待审批调用，按调用顺序）、`done`、`error`；`done` / `interrupted` / `error` 三者恰有一个作为最后事件
  - `type Request struct { Model ResolvedModel; System string; State []byte; Prompt string; Tools []ToolSpec; Responses []ToolResult; MaxTurns int }`；`State` 是上一轮的不透明状态（空 = 新对话）；`Responses` 恢复上一轮被中断的调用（内部 `Respond` + `WithToolResponses`；Genkit 在请求元数据里保存的兄弟调用已完成结果随 `State` 一起保留）
  - `type Result struct { State []byte; Messages []Message; Interrupts []ToolCall; Err *Error }`
  - `ai.CloseState(state []byte, responses []ToolResult) ([]byte, error)`：只把工具结果追加进状态、不请求模型（取消运行时闭合历史用）
  - `ai.NewEngine(logger *slog.Logger, secrets func() []string) (*Engine, error)`（`GENKIT_ENV=dev` 时返回错误）；`(*Engine).Run(ctx, Request) (events <-chan Event, wait func() Result)`；`(*Engine).Forget(serviceID int64)`（服务修改 / 删除时丢弃实例）；`(*Engine).Close()`
  - 事件通道缓冲 64；消费者停止读取不会让运行挂住：发送带 `ctx.Done()` 的 select；运行结束总能通过 `wait()` 取到 `Result`
  - 工具名在一次 `Run` 内必须唯一且匹配 `^[a-zA-Z0-9_-]{1,64}$`，否则返回 `bad_response` 以外的普通错误（`internal`）而不是 panic
  - `testllm.Server`：`Script(turns ...testllm.Turn)`；`Turn{Text []string; Calls []testllm.Call; Hang bool; Status int}`（一次响应里可以有多段文本和多个工具调用，`Call{ID, Name, Args}` 可指定 ID 以测试重复 ID）；`Requests() []testllm.Request`（system、messages、tools、headers 的原始 JSON）；`Release()` 放开 `Hang`
