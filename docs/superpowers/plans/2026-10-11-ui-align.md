## Global Constraints

- **Tokens win over mockup literals.** When an artboard's hex differs from tokens.json (#16A34A vs success #00a63e, #A3A3A3, old amber #92400E/#FCD34D), use the token. The tokens are the user's stated rule: all spacing, radius, type and colour come from tokens.
- **Type scale.** With the default font size 14, the scale is numerically the same as today. Only the default text size changes from 13 to 14 (user decision):
  - Native: `Xs f-3, Sm f-2, Base f-1, Body f, Lg f+1, Title f+2, Xl f+4, X2l f+6, Display f+15`, and `mygo th.FontSize = Body`.
  - Web: root font = f; `--text-xs 1rem-3px, sm 1rem-2px, base 1rem-1px, md 1rem, lg 1rem+1px`.
  - The default setting is `FontSize: 14`, with options 13/14/15/16.
- **Out of scope** (feature gaps, later plans, no UI stubs):
  - Model capability split (生成/判断, interface formats, 用途 section, TypeSafe/Decisions).
  - Scheduled send.
  - Time-based sync ranges and 邮箱行为 folder roles/purge.
  - Smart views.
  - Search filter chips (account/sender/time).
  - Move to junk.
  - 始终信任此发件人.
  - Quick-reply kind labels.
  - Plugin-card hint semantics.
  - Plugin tags on list rows.
  - Settings search.
  - 繁體中文/日本語 UI languages.
  - 只通知智能视图里的邮件.
  - Session-scoped "本次对话都允许".
  - Wit `+`/`@` mention.
  - Multi-turn undo history in the panel.
  - Model-written review summary.
  - Quoted injected text in the suspect note.
  - `[n]` inline citation links.
  - Folder counts ("6 个文件夹").
  - Sending from the drafts pane.
  - 添加附件 remedy on plugin warnings.
  - 与收件人相同的语言 auto entry.
- **No function lost.** Where the design drops an existing control, the control is kept, moved to the nearest sensible place, and ledgered. This covers:
  - General settings' AI and 邮件 sections.
  - The reader's star, mark unread and ⋯ menu.
  - 丢弃草稿 and the send-trust note in compose.
  - Manual-server security and username fields in onboarding.
- **Copy.** Chinese strings come from the design verbatim. Add en.go counterparts for every new key. Web strings go through `webui/strings.go`.
- **Tests.** Each task runs `go test ./...` and, for web tasks, `cd web && bun run test && bun run typecheck`. Existing tests that assert old copy or layout are updated to the new values, not deleted.
- Do not touch the untracked `assets/AppIcon.icon/`, `assets/.DS_Store` or `output/`.

## Review Focus

1. **Dark theme.** Every artboard is light only. New colours must come from tokens that have dark values, and nothing may be hard-coded:
   - Highlight: in dark mode the text on it stays neutral-950.
   - Status chips.
   - Theme thumbnails.
   - Tasks 1, 2, 6, 7 and 14 each add a dark assertion or a screenshot check.
2. **Font-size setting at 13 and 16.** Layout must not clip:
   - settings rows at 48 px min-height;
   - the toolbar icon groups;
   - the 76×48 thumbnails.
   Task 7 adds a test that renders a settings page at 16 and checks that no row's text is cut, using the harness's text-bounds helpers.
3. **Long and CJK search queries in highlight.** Matching is case-insensitive and rune-safe. Overlapping or empty queries and regex characters must not panic. Task 4 tests "C++", "", "邮件邮件" and mixed case.
4. **Drafts pane while the compose window edits the same draft.** "编辑中" must flip when the window opens or closes, without reselecting. Deleting from the pane while the window is open closes that window through the existing `DraftDeleted`. Task 5 tests both.
5. **The signature editor round-trip.** Rules:
   - An old plain-text signature, including one with `<` and newlines, must still render as escaped text.
   - HTML saved from the editor is sanitized with `mail.SanitizeCompose` before it reaches a draft.
   - An unsaved editor survives switching accounts in settings without writing to the wrong account.
   Task 10 tests all three.
