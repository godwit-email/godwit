# Godwit 图形界面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 mygo 原生 UI 做出 Godwit 桌面应用：窗口外框与托盘、添加账户、邮件（侧栏、会话列表、阅读、搜索、发件箱）、撰写（原生富文本编辑器）、Wit（Ask 页与撰写页面板、审批、修订 diff）、设置（账户、通用、模型服务、扩展）。完成后 `go run ./cmd/godwit` 是一个能日常使用的邮件客户端；所有界面行为都有基于 `ui.Tester` + 真实 `core.Service` + 本机假服务器的测试。

**Architecture:** `app/` 是界面层：一个 `App` 状态根（普通 Go 结构体）+ 每帧调用的 `View(c *ui.Context)`（mygo 立即模式）。所有 `core.Service` 调用都在 goroutine 里执行，结果通过注入的 `post func(func())`（生产环境是 `Window.Update`，测试里是可排空的队列）回到 UI 线程修改状态；状态只在 UI 线程上改，不需要锁。`internal/` 放与业务无关的界面基础：色板、主题、图标、组件库（shadcn Nova 外观，基于 mygo 的 `*Base` 组件）、多语言文案、Godwit 富文本模型（HTML / Markdown → 模型 → 渲染 / 回写 HTML）、富文本编辑器、逐词 diff。`cmd/godwit/` 是入口：单实例、窗口、托盘、关闭即隐藏、通知、开机启动。

**Tech Stack:** 前四份计划的全部依赖；`github.com/egoist/mygo v0.3.0` 的 `mygo` 与 `ui` 包（已在 go.mod）；新增 `github.com/yuin/goldmark`（Wit 输出的 Markdown → HTML，开 GFM 表格，不开原始 HTML）；内嵌 Geist / Geist Mono 字体（OFL）与 Lucide 图标 SVG（ISC），许可证文件随附。

**Spec:** `docs/superpowers/specs/2026-10-08-godwit-design.md`（第 3 节纪律、4、7.0–7.6、8、9、10）

**设计稿:** `docs/design/canvas/*.dc.html`（从 [Godwit UI 画布](https://claude.ai/artifact/LESLwyFigHSD8Yfvfimruq) 导出的 22 张画板，HTML 源文件；布局、尺寸、文案以它为准，颜色按下面的映射表换成色板）。每个任务列出它对应的画板。

**基线:** 从 `feat/plugins`（计划 4，PR godwit-email/godwit#5）拉出 `feat/gui`；前序 PR 合并后改基于 `main`。

**依据:** mygo v0.3.0 原生 UI 的已核实事实（来源：模块源码与 `docs/ui/*.md`，2026-10-10 调研）：

- 视图是 `func(c *ui.Context)`，每帧在主线程重建；状态是自己的结构体，控件绑定 `*string` / `*bool`；`ui.Element` 只在本次构建有效，不能存起来（存 `ui.Handle`、`ui.ListState`、`ui.TextBuffer`）。
- 后台 goroutine 改状态：`win.Update(func(){…})`（主线程执行后重绘）。`mygo.Dialog.*` 会阻塞，只能在 goroutine 里调。
- 测试：`ui.NewTester(view, w, h)` 是无 GPU 的离屏渲染器，带模拟输入（`Click(text)`、`Key`、`Type`、`Compose`、`Command`、`Scroll`、`ChooseMenuItem`、`SetDark`）和观察接口（`Texts()`、`HasText`、`Find`、`Focused`、`Clipboard`、`OpenedURLs`、`Image()`）。没有元素树查询，所以**断言看得见的文字和 App 状态**；只有图标的控件必须 `.Label(…)` 才能被点到；虚拟列表只构建可见行。Tester 直接跑视图，不经过 `Window.Update`。
- 文本：`ui.RichText(c, spans…)` 显示只读富文本（行内 `ui.Link` 可点）；没有 HTML 渲染器，没有可编辑富文本。自定义编辑器 = 实现 8 个方法的 `TextInputClient`（UTF-16 区间）+ `HandleInput` + `Draw`，用 `ui.ShapeRichText` / `TextLayout` 算光标、命中和选区，撤销自己做。
- 菜单（`ContextMenu`、`MenuButton`）是系统原生弹出菜单；托盘 `mygo.NewTray`；通知 `mygo.NewNotification`（macOS 只在打包后的应用里可用）；`App.SetOpenAtLogin`；`App.RequestSingleInstanceLock`；关闭即隐藏用 `win.OnClose` + `PreventDefault` + `Hide`，`App.OnActivate` 再显示。
- `mygo.Bind()` 只服务网页视图，原生 UI 不用。

### 规格解释（本计划采用，已同步到 spec）

- **第 3 节「`Bind()` 生成的 TS 客户端是对外 API 的第一个使用者」与第 9 节「对 `Bind()` 和 JSON-RPC 跑同一套契约测试」**：原生 UI 直接调用 Go 的 `*core.Service`，没有 `Bind()`。纪律不变：`app/` 只经 `*core.Service`（以及 `core/mail` 等纯函数辅助）访问核心，用 import 边界测试保证；契约测试留给计划 6（JSON-RPC 与进程内调用对比）。
- **core 没有的能力不做界面**（不在 v1 Service API 里）：智能视图（「待回复」「订阅与账单」）、「始终信任此发件人」、「定时发送」、审批卡片的「本次对话都允许」（改为有多个待审批项时显示「全部允许」，即 `ResolveAll`）、按对话选择模型（模型标签显示默认模型，点击跳到设置）。设置里的「只通知智能视图里的邮件」开关因此隐藏。这些记入 spec 第 10 节待定。
- **列表的「未读」筛选**在客户端按已加载的页过滤（未读不足一屏时继续加载下一页），不新增 Service API。
- **发件箱与草稿的入口**：每个账户的文件夹列表末尾，发件箱有内容时显示「发件箱 n」；角色为 `drafts` 的文件夹打开本地草稿列表（`ListDrafts`）。
- **深色模式**（spec 第 10 节仍待设计稿）：本计划暂定 `Window` = `neutral-900` 与 `neutral-800` 的 oklch 中点、`Sidebar` = `neutral-900`、`Background` = `neutral-950`、`Foreground` = `neutral-50`、`Muted` = `neutral-400`、`Border` = `neutral-800`、`Primary` = `neutral-200`（文字 `neutral-900`），都来自色板；设计稿出来后只改 `internal/theme` 一处。
- **邮件里的表格**：HTML 邮件大量用表格排版。转换时，含 `<th>` 且最多 8 列、单元格只有行内内容的表格保留为表格块；其余表格按单元格顺序拆成段落。Wit 的 Markdown 表格（GFM）总是表格块。
- **远程图片**：用户点「加载图片」后，由界面层下载（只允许 `http` / `https`，不带 Cookie，单张 5 MB、15 秒），只在本次查看中显示，不缓存到磁盘。
- **界面语言**：界面文案走 `internal/i18n`，v1 提供 `zh-CN`（以设计稿为准）和 `en`；默认取系统语言，设置里可改。

## Global Constraints

- 前四份计划的 Global Constraints 全部继续有效（Go 1.27.1、`CGO_ENABLED=0`、凭据只进钥匙串、AI 与扩展不能发信）。
- **界面只经 `*core.Service` 访问核心**：`app/`、`internal/`、`cmd/godwit/` 不得 import `core/store`、`core/mailsync`、`core/send`、`core/conn`、`core/gateway`、`core/skills`、`core/internal/...`；允许 `core`、`core/mail`（纯函数）、`core/ai`、`core/events`、`core/auth`、`core/plugins` 的类型与常量。Task 1 的 `TestImportBoundary` 解析源码 import 来保证。
- **UI 线程纪律**：视图里不做阻塞调用，不起 goroutine；Service 调用一律 `go func(){ …; a.post(func(){ 改状态 }) }()`；状态只在 UI 线程上改；不存 `ui.Element`。

- **文案**：所有用户可见文字走 `i18n.T(key)`；`zh-CN` 逐字取设计稿（画板里的占位符如 `[MODEL]` 换成真实数据）；`en` 由实现者翻译；两种语言键集合一致（测试检查）。
- **无障碍与可测**：只有图标的按钮必须 `.Label(T(…))`；所有布尔设置用 Switch；可点击元素用 `ButtonBase` 等可聚焦组件，不用裸 `Box` + `Clicked`。
- **尺寸**（shadcn Nova，对齐设计稿）：按钮高 32（小号 28）、圆角 6–8；输入框高 32；图标栏 56 宽、按钮 40；侧栏 248 宽、左上圆角 14；顶栏高 44；侧栏行高 32；正文基准字号取 `Settings.FontSize`，邮件正文取 `Settings.BodyFontSize`；`Density` 为 `comfortable` 时行高与内边距 ×1.25。
- **窗口**：默认 1280×820，最小 960×600，`StateKey: "main"`；macOS `TitleBarHiddenInset` + `VibrancySidebar`；Windows `TitleBarHeight: 40` + `VibrancyMica`；Linux 默认标题栏样式隐藏、按钮让位由 `c.TitleBar()` 给出。
- **测试**：`app` 的测试用 `ui.NewTester` + `core/coretest` 起的真实 Service（钥匙串 mock、假 IMAP / SMTP / 模型服务都在本机）；不访问真实网络、钥匙串、浏览器；平台能力（打开链接、文件对话框、通知、托盘、剪贴板 HTML、开机启动、主题来源）通过 `Platform` 接口注入，测试用假实现记录调用。
- 新增的第三方文件（字体、图标）带许可证放在同目录（`OFL.txt`、`LICENSE-lucide.txt`）。

## Review Focus

1. **大邮箱**：几千个会话的文件夹打开、滚动、跳到底部 —— 列表虚拟化、按页加载（`limit` 50），不一次性取完；滚到底部自动加载下一页且不重复。→ Task 6 `TestThreadListPagesOnScroll`。
2. **事件丢失或成串到达**：事件总线满了会丢最旧的事件 —— 界面不依赖单个事件，收到任何事件都重新查询当前可见数据（合并为每 250 ms 至多一次），最终和数据库一致。→ Task 4 `TestEventBurstConverges`。
3. **恶意或超大的 HTML 正文**（2 MB、嵌套 500 层、上万行表格、`javascript:` 链接）—— 转换有深度上限（20 层后拍平）、块数上限（5000 块后截断并提示「显示原文」）、链接只保留 `http` / `https` / `mailto`，2 MB 正文转换加首帧渲染在 1 秒内。→ Task 9 `TestHostileHTML`。
4. **中文输入法**：编辑器里组合输入（拼音未上屏、上屏、取消）、选中后输入、撤销 —— 正文和保存的 HTML 都正确，组合中的文字不会被自动保存。→ Task 12 `TestIMECompose`。
5. **Wit 正在写正文时用户还在打字 / 审批过期**：运行中与有待确认提案时正文锁定，输入被忽略并提示；草稿版本过期（`ErrStaleDraft`）时重新加载而不是覆盖，用户未保存的文字不丢（先保存再让 Wit 开始）。→ Task 15 `TestEditorLockedDuringRun`、`TestStaleDraftReloads`。

- Produces：
  - `worddiff`：`type Op struct{ Kind OpKind /*Same, Del, Ins*/; Text string }`；`func Diff(old, new string) []Op`（按词切分：拉丁文按空白与标点，中日韩按单字；LCS / Myers，输入超过 2 万词时退化为整段替换）；`func ChangedRatio(ops []Op) float64`（改动词数 / 两侧词数的较大者）

  - 锁定：运行中或有待确认提案时编辑器 `ReadOnly`，键入时提示一次「先接受或拒绝助手的修改」；开始任何 Wit 运行前先保存草稿（避免过期）
