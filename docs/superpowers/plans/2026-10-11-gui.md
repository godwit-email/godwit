# Godwit 图形界面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 mygo 原生 UI 做出 Godwit 桌面应用：窗口外框与托盘、添加账户、邮件（侧栏、会话列表、阅读、搜索、草稿、发件箱）、撰写（原生富文本编辑器）、Wit（Ask 页与撰写页面板、审批、修订审阅）、设置（账户、通用、模型服务、扩展、隐私、关于）。完成后 `go run ./cmd/godwit` 是一个能日常使用的邮件客户端；界面行为都有基于 `ui.Tester` + 真实 `core.Service` + 本机假服务器的测试。

**Architecture:** `app/` 是界面层：一个 `App` 状态根（普通 Go 结构体）+ 每帧调用的 `View(c *ui.Context)`（mygo 立即模式）。Service 调用都在 goroutine 里执行，结果经注入的 `post func(func())`（生产环境是 `Window.Update`，测试里是可排空的队列）回到 UI 线程改状态；状态只在 UI 线程上改。时间经注入的 `Clock` 读取与调度，测试可推进。同一资源的写入（设置、每份草稿）走串行写队列。`internal/` 放与业务无关的界面基础：色板、主题、图标、组件库（shadcn Nova 外观）、多语言文案、Godwit 富文本模型（安全 HTML / Markdown → 模型 → 渲染 / 回写 HTML）、富文本编辑器、带格式的逐词 diff。`cmd/godwit/` 是入口：单实例、窗口、托盘、关闭即隐藏、通知、开机启动。

**Tech Stack:** 前四份计划的全部依赖；`github.com/egoist/mygo v0.3.0` 的 `mygo` 与 `ui` 包（已在 go.mod）；新增 `github.com/yuin/goldmark`（Wit 输出的 Markdown → HTML，开 GFM 表格与删除线，不开原始 HTML）；内嵌 Geist / Geist Mono 字体（OFL）与 Lucide 图标 SVG（ISC），许可证随附。

**Spec:** `docs/superpowers/specs/2026-10-08-godwit-design.md`（第 3 节纪律、4、5.5「邮件 HTML 显示契约」、7.0–7.6、8、9、10）

**设计稿:** `docs/design/canvas/*.dc.html`（从 [Godwit UI 画布](https://claude.ai/artifact/LESLwyFigHSD8Yfvfimruq) 导出的 22 张画板；布局、尺寸、文案以它为准，颜色按下面的映射表换成色板）。每个任务列出对应画板。

**基线:** 从 `feat/plugins`（计划 4，PR godwit-email/godwit#5）拉出 `feat/gui`；前序 PR 合并后改基于 `main`。

**依据:** mygo v0.3.0 原生 UI 的已核实事实（模块源码与 `docs/ui/*.md`，2026-10-10 调研，2026-10-11 计划评审复核）：

- 视图是 `func(c *ui.Context)`，每帧在主线程重建；状态是自己的结构体，控件绑定 `*string` / `*bool`；`ui.Element` 只在本次构建有效，不能存（存 `ui.Handle`、`ui.ListState`、`ui.TextBuffer`）。`ui.Element` 是外部类型，不能给它加方法：组件的变体用参数或选项结构体表达。
- 后台改状态：`win.Update(func(){…})`（异步，主线程执行后重绘）。`mygo.Dialog.*` 阻塞，只在 goroutine 里调。
- 测试：`ui.NewTester(view, w, h)` 离屏渲染 + 模拟输入（`Click(text)` 按文字或 `Label`、`Key`、`Type`、`Compose`、`Command`、`Scroll`、`ChooseMenuItem`、`SetDark`、`SetTitleBar`、`SetClipboard`）+ 观察（`Texts()`、`HasText`、`Find`、`Focused`、`Clipboard`（纯文本）、`OpenedURLs`、`Image()`）。没有元素树查询：断言可见文字与 App 状态；只有图标的控件必须 `.Label(…)`；虚拟列表只构建可见行；`Frame()` 不推进时间。
- 文本：`ui.RichText(c, spans…)` 只读富文本（行内 `ui.Link`）；没有 HTML 渲染器与可编辑富文本。自定义编辑器 = 实现 `ui.TextInputClient`（8 个方法，UTF-16 区间，其中 `Selection() ui.TextInputSelection`）+ `HandleInput` + `Draw`，用 `ui.ShapeRichText` / `TextLayout` 算光标、命中、选区，撤销自己做。同一字族可注册多个字重（macOS 追加 face）。
- `ui.Oklch` 返回经色域映射、量化后的 `ui.Color`，不保留 L/C/H。
- 菜单是系统原生弹出菜单；托盘 `mygo.NewTray`；通知 `mygo.NewNotification`（macOS 只在打包后的应用里可用）+ `App.OnNotificationClick`；`App.SetOpenAtLogin`；`App.RequestSingleInstanceLock`；关闭即隐藏用 `win.OnClose` + `PreventDefault` + `Hide`。
- core 的已核实事实：`SaveDraft` 更新已有草稿时不改 `account_id`；`mail.Sanitize` 把链接放在 `data-href`（撰写清洗保留 `href`）；`Send` 发送数据库里的草稿，只入队，发件 worker 只在 `Options.AutoSync` 时运行；`SetFlags` / `Move` / `Delete` 一次调用只能是同一账户的邮件；`SubscribeConversation` 只订阅之后的事件，流会丢弃积压的非终止事件；`ResolveAll` 的参数是运行 ID；`SetSettings` 整体替换；同步范围 1–100000；没有删除草稿与附件缓存占用 / 清理的 Service 方法（Task 1 补上）。

### 规格解释（本计划采用，已同步到 spec 第 3、4、9、10 节）

- 原生 UI 直接调用 `*core.Service`，不经 `Bind()`；纪律由 import 边界测试保证；契约测试随计划 6。
- core 没有的能力不做界面：智能视图（及「只通知智能视图里的邮件」开关）、「始终信任此发件人」、定时发送、审批卡片的「本次对话都允许」（改为有多个待审批项时「全部允许」= `ResolveAll(runID)`）、按对话选择模型（模型标签显示默认模型，点击去设置）、按时间设同步范围（用 2000 / 10000 / 100000 封三档）。
- 撰写页「生成中」：正文区显示占位（「Wit 正在写…」+ 骨架行），流式文字显示在 Wit 面板；core 写入草稿后正文刷新。
- 列表「未读」筛选在客户端按已加载页过滤（不足一屏时继续加载）。
- 发件箱有条目时在账户文件夹末尾显示「发件箱 n」；角色 `drafts` 的文件夹打开本地草稿列表（`ListDrafts`）。
- 深色模式暂定值见下方 `theme.Dark()`；邮件正文颜色只在与背景对比度 ≥ 3:1 时使用，否则用前景色。
- 邮件里的表格：含 `<th>`、最多 8 列、单元格只有行内内容的保留为表格块（单表最多 2000 个单元格，超出截断）；其余按单元格顺序拆成段落。Wit 的 GFM 表格总是表格块。
- 界面语言：`zh-CN`（以设计稿为准）与 `en`，默认取系统语言。

## Global Constraints

- 前四份计划的 Global Constraints 全部继续有效（Go 1.27.1、`CGO_ENABLED=0`、凭据只进钥匙串、AI 与扩展不能发信）。
- **界面只经 `*core.Service` 访问核心**：`app/`、`internal/`、`cmd/godwit/` 不得 import `core/store`、`core/mailsync`、`core/send`、`core/conn`、`core/gateway`、`core/skills`、`core/internal/...`、`core/coretest`（测试文件除外）；允许 `core`、`core/mail`（纯函数）、`core/ai`、`core/events`、`core/auth`、`core/plugins` 的类型与常量。`TestImportBoundary` 解析源码 import 保证。
- **UI 线程纪律**：视图里不做阻塞调用、不起 goroutine、不调 `time.Now`（用 `a.clock`）；Service 调用一律经 `a.do`；状态只在 UI 线程上改；不存 `ui.Element`。
- **写入顺序**：同一资源的写入经 `writeQueue` 串行，提交不可变快照并带编辑代次；只有确认保存的代次才清除「未保存」。异步查询带路由 / 视图代次，过期结果丢弃。
- **颜色只来自 `internal/palette`**（经 `internal/theme` 的语义变量）：`app/`、`internal/kit/` 里不出现 `ui.Hex(`、`ui.RGB(`、`ui.RGBA(`、`ui.Color{`（`TestNoColorLiterals`）。邮件正文自带的颜色属于内容，由 `internal/richtext` 处理。设计稿灰色换算：

- **文案**：用户可见文字走 `i18n.T(key)`；`zh-CN` 逐字取设计稿（占位符如 `[MODEL]` 换成真实数据）；`en` 由实现者翻译；两种语言键集合一致。
- **无障碍与可测**：只有图标的按钮必须 `.Label(T(…))`；布尔设置用 Switch；可点击元素用可聚焦组件（`ButtonBase` 等）。
- **尺寸**（shadcn Nova，对齐设计稿）：按钮高 32（小号 28）、圆角 6–8；输入框高 32；图标栏 56 宽、按钮 40；侧栏 248 宽、左上圆角 14；顶栏高 44；侧栏行高 32；界面字号取 `Settings.FontSize`，邮件正文取 `Settings.BodyFontSize`；`Density` 为 `comfortable` 时行高与内边距 ×1.25。
- **窗口**：默认 1280×820，最小 960×600，`StateKey: "main"`；macOS `TitleBarHiddenInset` + `VibrancySidebar`；Windows `TitleBarHiddenInset` + `TitleBarHeight: 40` + `VibrancyMica`；Linux `TitleBarHiddenInset`（按钮位置由 `c.TitleBar()` 给出）。
- **邮件内容的资源预算**（每次查看一封邮件）：富文本转换在 goroutine 里做；最多 5000 块、嵌套 20 层、单表 2000 单元格、单块 2 万个行内片段；远程图片最多 50 张、合计 20 MB、单张 5 MB、并发 4、单张解码不超过 4000 万像素（先 `image.DecodeConfig`）、15 秒；只允许 PNG、JPEG、GIF、WebP（按内容识别）；切换邮件时取消。
- **测试**：`app` 的测试用 `ui.NewTester` + `core/coretest` 的真实 Service（钥匙串 mock、假 IMAP / SMTP / 模型服务 / MCP 都在本机）+ 假 `Clock`；不访问真实网络、钥匙串、浏览器；平台能力经 `Platform` 接口注入，测试用假实现。跨页面的验收放在页面都实现之后的任务里；早期任务只断言路由意图（`a.route`）。性能阈值只在单独的、`-race` 下跳过的测试里检查。
- 新增的第三方文件（字体、图标）带许可证放在同目录（`OFL.txt`、`LICENSE-lucide.txt`）。

## Review Focus

1. **大邮箱与分页一致性**：几千个会话的文件夹打开、滚动、在第三页上改已读或删除、刷新期间来新信 —— 按页加载（每页 50），刷新重查已加载的全部范围，按 ID 去重，保持选中与滚动锚点。→ Task 7 `TestThreadListPagesOnScroll`、`TestRefreshKeepsLoadedRange`。
2. **事件丢失或成串到达**：界面不依赖单个事件，收到任何事件都重查当前可见数据（合并为每 250 ms 至多一次），最终和数据库一致。→ Task 5 `TestEventBurstConverges`。
3. **恶意或超大的 HTML 正文**（2 MB、嵌套 500 层、上万行表格、巨大图片、`javascript:` 链接）—— 转换与图片都受预算约束、不在 UI 线程上做，链接只保留 `http` / `https` / `mailto` 且打开前显示真实地址。→ Task 10 `TestHostileHTML`、Task 11 `TestImageBudgets`、`TestLinkConfirm`。
4. **中文输入法**：组合输入（未上屏、上屏、取消）、选中后输入、撤销 —— 正文与保存的 HTML 都正确，组合中的文字不会被保存或发送。→ Task 13 `TestIMECompose`、Task 14 `TestNoSaveWhileComposing`。
5. **输入后马上发送 / Wit 写正文时用户在打字 / 草稿被别处改了**：发送前先把最新内容保存成功；运行中与有待确认提案时正文锁定；版本冲突时保留本地副本让用户选择，不自动覆盖任何一方。→ Task 14 `TestSendFlushesLatest`、`TestStaleDraftConflict`，Task 16 `TestEditorLockedDuringRun`。
