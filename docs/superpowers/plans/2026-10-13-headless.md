# Godwit headless、JSON-RPC 与 MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让同一个 `core.Service` 通过本机 JSON-RPC 与 MCP 对外可用：`godwit --headless` 无界面常驻；GUI 可在设置里打开「本机 API」；`godwit mcp` 作为 MCP（stdio）服务端把只读 + 草稿的子集交给 AI agent；进程内与 JSON-RPC 两个出口跑同一套契约测试。

**Architecture:** 一个数据目录同一时刻只有一个进程拥有 Service：GUI 与 headless 在 `core.New` **之前**取得数据目录里的排他文件锁，持有到 Service 关闭。拥有者可在数据目录下的 Unix 域套接字（Go 在 Windows 10 1803+ 同样支持）上提供 JSON-RPC 2.0（每行一条消息）。分发用反射：方法名就是 `*core.Service` 的导出方法名，参数是去掉 `context` 后的 JSON 数组；返回 channel 的方法变成「流」，用通知推送、可取消，取消后服务端把剩余事件读完以回收 Service 的流。连接先用 token 认证并声明角色：`full` 或 `mcp`（按方法与参数的白名单）。`godwit mcp` 是薄桥：go-sdk 的 stdio MCP 服务端，工具调用转成 `mcp` 角色的 JSON-RPC 调用，自己不打开数据库。错误码注册与秘密脱敏放在组合包 `rpcbind`，core 不依赖 rpc。

**Tech Stack:** 标准库（`net`、`encoding/json`、`reflect`、文件锁用 `syscall.Flock` / `golang.org/x/sys/windows.LockFileEx`，x/sys 已在 go.mod）；已有的 `github.com/modelcontextprotocol/go-sdk v1.8.0`。不新增第三方依赖。

**Spec:** `docs/superpowers/specs/2026-10-08-godwit-design.md`（第 2、3、4 第 5 条、5.5、8、9 节；本计划修订第 3、4、5.5 节）

**基线:** 从 `feat/model-services`（PR godwit-email/godwit#7）拉出 `feat/headless`。

**评审修订（Codex 计划评审）:** 所有权锁先于 `core.New`；反射覆盖多返回值与无返回值并对真实方法集做覆盖测试；流取消后排空回收；连接级配额、有界发送队列、写超时、请求取消；未知错误固定文案；类型错误用显式安全编码，类型优先于 sentinel；契约测试的进程内一侧直接调用类型化 Service；MCP 读取走不下载内联图片的新方法，`NewDraft` 在 `mcp` 角色只允许 new / reply / reply_all；角色只是最小权限而非隔离，文案与 spec 如实说明；目录权限与残留套接字在持锁后处理；MCP 结果只输出带不可信标记的文本；草稿工具读后合并、要求 revision；Windows 由 CI 原生跑测试，命令入口可在进程内测试。

### 规格解释（同步到 spec 第 3、4、5.5 节）

- **一个数据目录一个拥有者**：GUI 与 `--headless` 启动时先取得 `<DataDir>/godwit.lock` 的排他锁（失败即退出，不做任何数据库操作），持有到 Service 关闭。其他进程（脚本、`godwit mcp`）只能通过拥有者的 JSON-RPC 套接字访问。mygo 的单实例锁保留，只负责 GUI 的「再次打开时聚焦已有窗口」。
- **本机 API 的信任边界是同一个操作系统用户**：token 防其他用户和误连，不防同一用户的恶意程序。`full` 角色就是「用户自己的程序」，可以发送邮件、修改账户与设置——这是对第 5.5 节「发送永远由用户在撰写页点击」的明确例外，只适用于用户主动开启的本机 API（GUI 默认关闭；headless 总是开启）。通过本机 API 的发送写一条审计（来源 `local_api`）。
- **`mcp` 角色是最小权限，不是隔离**：持有 token 的程序也能声明 `full`。`mcp` 的意义是 `godwit mcp` 这座桥本身只请求只读与草稿能力，AI agent 无论怎么被诱导，经由 MCP 都调不到发送、删除、设置、账户、扩展、审批。MCP 的草稿写入写审计（来源 `mcp`）。
- **`godwit mcp` 需要正在运行的拥有者**（GUI 已开启本机 API，或 headless）；找不到时清楚报错退出，不自行启动。
- MCP 输出的每个邮件来源字段都包在不可信标记里；标记是给模型的提示，真正的约束是权限白名单。

## Global Constraints

- 前六份计划的 Global Constraints 全部继续有效（Go 1.27.1、无 cgo 构建、凭据只进钥匙串且不进日志 / 错误 / 事件、迁移只追加、AI 与扩展不能发信）。
- **MCP 没有发送路径**：`mcp` 角色的白名单（方法 + 参数）在测试里逐项列出；没有任何能导致发信、删除邮件、修改账户 / 设置 / 扩展 / 模型服务、处理审批、下载附件的调用。
- 文件：锁 `<DataDir>/godwit.lock`；套接字 `<DataDir>/godwit.sock`；token `<DataDir>/api-token`（32 字节随机，hex，每次启动服务端时重新生成，0600）。数据目录在 Unix 上持锁后检查并收紧为 0700（属主不是当前用户时报错）；Windows 依赖用户目录的默认 ACL，自定义 `--data-dir` 的 ACL 不做校验（文档说明）。Unix 套接字路径超过上限（约 104 字节）时报清楚的错误。
- 连接预算：单条入站消息 ≤ 16 MB；每连接进行中的请求与活动流合计 ≤ 32；每连接发送队列 ≤ 1024 条或 32 MB，满了就断开该连接（取消它的所有流）；单次写超时 10 秒；同时连接数 ≤ 16；认证前只接受 `hello`，5 秒内未认证即断开。
- 错误：未注册错误一律返回固定文案「internal error」（服务端日志记录脱敏后的原文）；已注册错误返回稳定码与经过脱敏的安全字段；任何错误、日志、事件里都不得出现 token、API key、密码。
- 测试全部在本机；`rpc` 的测试在 CI 的 Windows 任务上原生运行（AF_UNIX 需要 Windows 10 1803+ / Server 2019+，GitHub 的 windows-latest 满足）。

## Review Focus

1. **两个进程同时拥有数据目录**：GUI（本机 API 关）与 headless、两个 headless、同时启动 —— 后来者在任何数据库操作之前失败；不同数据目录可以并存。→ Task 3 `TestOwnerLock*`。
2. **`mcp` 角色越权与副作用**：调用发送、删除、设置、审批、转发草稿（下载附件）、读取完整邮件（下载内联图片）—— 服务端拒绝，状态无变化，无网络请求。→ Task 3 `TestMCPRoleAllowlist`、`TestMCPReadDownloadsNothing`。
3. **流与断线**：订阅、Ask / Assist 流在积压事件时被取消或断线 —— 服务端排空 Service 的流，相关 goroutine 退出；慢客户端不拖垮服务端。→ Task 1 `TestStreamCancelDrains`、`TestSlowConsumerDisconnected`。
4. **两个出口行为不一致**：类型、零值、时间、多返回值、错误 `Is/As`。→ Task 4 契约测试（进程内一侧直接调用类型化 Service）。
5. **错误泄露**：未知错误、包装错误、插件警告里的文本 —— 不泄露秘密；未知错误不回显原文。→ Task 2 `TestUnknownErrorIsGeneric`、`TestErrorsCarryNoSecrets`。

### Task 1: JSON-RPC 传输、反射分发与流

**Files:**
- Create: `rpc/jsonrpc.go`, `rpc/dispatch.go`, `rpc/client.go`
- Test: `rpc/jsonrpc_test.go`, `rpc/dispatch_test.go`（外部测试包 `rpc_test`）

**Interfaces:**
- Produces:
  - **支持的 JSON-RPC 子集**：每行一个 JSON 对象；`id` 只接受正整数（字符串 ID、重复的在途 ID、批量数组 → 错误响应或断开，见测试）；`params` 只接受数组；无 ID 的请求只接受 `$/` 开头的控制通知。所有消息都带 `"jsonrpc":"2.0"`
  - 控制消息：流事件 `{"jsonrpc":"2.0","method":"$/stream","params":[S, event]}`、流结束 `$/stream.end` `[S]`（流因错误结束时 `[S, error]`）、客户端取消流 `$/stream.cancel` `[S]`、客户端取消请求 `$/cancel` `[id]`
  - **顺序**：同一连接的所有出站消息经一个有序发送队列；返回流的响应一定先于该流的任何通知
  - `type Dispatcher struct{…}`；`func NewDispatcher(target any, expose func(method string) bool) (*Dispatcher, error)`：反射 `target` 的导出方法；`expose` 决定是否暴露。**支持的签名**：可选首参 `context.Context`；返回值为 `()`（结果 `null`）、`(T)`、`(error)`、`(T, error)`、`(T1, T2, …, error)`（结果是 JSON 数组）、`(<-chan T, error)`、`(<-chan T, func())`。暴露的方法签名不受支持时 `NewDispatcher` 返回错误（不静默跳过）
  - 流：调用时创建可取消 context；返回 channel 后响应 `{"stream": S}`；元素逐个作为 `$/stream` 通知；channel 关闭发 `$/stream.end`。取消（客户端取消、断线、连接因预算断开、服务端关闭）时：取消 context、调用返回的 `func()`（若有），然后**继续读 channel 直到关闭并丢弃**，确保 Service 一侧的 pump 能退出
  - `func ServeConn(ctx context.Context, conn io.ReadWriteCloser, d *Dispatcher, opts ConnOptions) error`；`ConnOptions{ MaxMessage int; MaxActive int /*请求 + 流，32*/; QueueMessages int /*1024*/; QueueBytes int /*32 MB*/; WriteTimeout time.Duration /*10 s*/; Hello func(params []json.RawMessage) (allow func(method string, params []json.RawMessage) bool, result any, err error); AuthTimeout time.Duration; EncodeError func(error) *WireError }`
  - 客户端：`func NewClient(conn io.ReadWriteCloser) *Client`；`Call(ctx, method, result any, args ...any) error`（`result` 可以是指向切片的指针，用于多返回值；ctx 取消时发送 `$/cancel`）；`Stream(ctx, method, args ...any) (events <-chan json.RawMessage, cancel func(), err error)`（单个读循环按序处理：先登记流再分发后续通知；每个流有有界缓冲，调用方不读时只影响该流——缓冲满则客户端取消该流并让 `events` 以错误结束）；`DecodeError func(*WireError) error`（Task 2 注入）

- [ ] **Step 1: 写失败的测试**（测试用 target 结构体）：`TestDispatchSignatures`（全部支持的签名，含多返回值数组与 `null`）；`TestNewDispatcherRejectsUnsupported`（暴露的方法签名不支持 → 错误）；`TestDispatchRejects`（未知 / 未暴露方法、参数个数与类型错误、字符串 ID、批量、重复在途 ID）；`TestStreamOrdering`（立即产生首事件的流：客户端先收到响应再收到事件，不丢）；`TestStreamCancelDrains`（target 的流在取消后仍有积压事件且只在被读完后才退出 → 取消后 target 的 pump 退出，用退出信号断言，不用全局 goroutine 计数）；`TestStreamCancelOnDisconnect`；`TestRequestCancel`（`$/cancel` → target 的 ctx 被取消）；`TestServerLimits`（超 16 MB 的行 → 断开；第 33 个活动请求或流 → `too many requests`）；`TestSlowConsumerDisconnected`（客户端不读，服务端队列满 → 断开该连接，其他连接正常）；`TestClientStreamBackpressure`（客户端不读某个流 → 只有该流被取消，其他调用正常）。

### Task 3: 所有权锁、套接字服务端、token、角色、读取路径与审计

**Files:**
- Create: `ownerlock/lock.go`（`lock_unix.go`、`lock_windows.go`）、`rpc/server.go`、`rpc/roles.go`、`core/messagetext.go`

- Test: `ownerlock/lock_test.go`, `rpc/server_test.go`, `rpcbind/server_test.go`, `core/messagetext_test.go`

**Interfaces:**
- Produces:
  - `ownerlock.Acquire(dataDir string) (release func() error, err error)`：创建目录（0700）；Unix 上若目录已存在则检查属主为当前用户并 `chmod 0700`；打开 `godwit.lock` 并取非阻塞排他锁（Unix `flock(LOCK_EX|LOCK_NB)`，Windows `LockFileEx(LOCKFILE_EXCLUSIVE_LOCK|LOCKFILE_FAIL_IMMEDIATELY)`）；已被锁 → `ErrAnotherOwner`；锁随进程退出自动释放
  - `rpc.Listen(dataDir string, d *Dispatcher, opts ServerOptions) (*Server, error)`：**前提是调用者已持有所有权锁**（文档注明）；`godwit.sock` 若存在且是套接字文件 → 删除（持锁意味着它一定是残留）；不是套接字 → 报错不删；监听 `unix`，文件 0600（Unix）；生成 token 写 `api-token`（临时文件 + 改名，0600）；`ServerOptions{ Conn ConnOptions; MaxConns int /*16*/; Version string }`；`(*Server).Serve(ctx) error`；`(*Server).Close() error`（停止接受、断开所有连接、等所有流排空、删除自己创建的套接字与 token 文件）；`(*Server).Path() string`
  - 认证：首个请求 `hello`，参数 `[token, role, client]`；token 常量时间比较；`role` 为 `full` 或 `mcp`；成功返回 `{"server": "godwit/<version>", "role": role}`；失败 → 错误响应并断开；认证后再次 `hello` → 错误
  - `rpc.MCPAllowed(method string, params []json.RawMessage) bool`：白名单 `ListAccounts`、`ListFolders`、`ListThreads`、`GetThread`、`ListMessages`、`GetMessageText`、`Search`、`ListDrafts`、`GetDraft`、`NewDraft`（仅当第 2 个参数是 `"new"`、`"reply"`、`"reply_all"`）、`SaveDraft`；其余全部拒绝（`forbidden`）
  - `rpc.Dial(dataDir, role, client string, codec *Codec) (*Client, error)`
  - core：`type MessageText struct { MessageSummary; AccountID int64; ReplyTo string; Text string; Truncated bool; Attachments []AttachmentInfo }`；`func (s *Service) GetMessageText(ctx, id int64) (MessageText, error)`：从数据库读纯文本与元数据，**不**处理 HTML、不读取或下载任何附件 / 内联图片
