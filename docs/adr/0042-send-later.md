# 稍后发送：排定的邮件放在发件箱里，只由用户在界面里排定

撰写窗口在「发送」旁边加「稍后发送」：选一个日期和时间，邮件到点发出。主窗口侧栏里多一个「已排定」，列出还在等待的邮件，可以取消，也可以修改（#670）。

这是一种无人值守的外发：用户点完按钮离开，邮件在之后某个时刻、没有人在键盘前时发出。按 [0003](0003-no-extension-can-send.md) 的最后一段，它是「之后会在无人参与时自动外发的持久状态」，所以下面几条都从这一点出发。

## 决定

- **放在发件箱里，不另建队列。** 排定的邮件就是一个发件箱条目（`outbox`），新增 `send_at` 列记下用户选的时间（unix 毫秒，普通发送为 NULL），`send_after` 同样设为这个时间（但不早于 10 秒撤销窗口的结束）。发件箱本来就按 `send_after` 等待、到点由同一个 `processOutbox` 发出，所以排定发送和普通发送走完全相同的路径：至多一次、按 SMTP 回复分级重试、认证失败暂停、发送待核实，全部照 [0006](0006-send-at-most-once.md)。issue 里说的「操作队列（`ops`）」在 [GLOSSARY](../../GLOSSARY.md) 里指推送到服务器的标记、移动和删除，发信一直在发件箱里，这里沿用发件箱。
- **发送前检查在排定时运行。** `message.beforeSend` 和其余检查在用户点「排定发送」时照常运行，警告由用户当场决定「仍然发送」，阻止则不进入发件箱。之后草稿挂在条目上、只读，到点发出的正是检查过的那一版。到点时不再运行：那时没有人能回应警告，而且 [0006](0006-send-at-most-once.md) 的撤销窗口也是同样做法。
- **日期头取排定的时间。** 邮件在入队时生成，`Date` 头写成排定的时间（不早于入队时刻），收件人看到的是到点发出的时间，而不是写信的时间。到点时 Godwit 没在运行、晚发了，`Date` 仍是排定的时间。
- **只在后端运行期间发送。** 没有服务器端的定时发送：到点时 Godwit 后端（窗口或后台运行）没在运行，就在下次启动后的第一轮同步里发出。界面在「稍后发送」弹层和「已排定」列表上都写明这一点。[0006](0006-send-at-most-once.md) 的「排队过久转人工」从排定的时间算起：超过 3 天还没发出（比如一直没打开 Godwit），条目转为失败、原因「排队时间过长」，交给用户修改、重新发送或丢弃，不会在几天后悄悄发出。
- **发出前一直可以取消。** 排定的条目在开始发送之前都是「排队」状态，`CancelOutbox` 能把它取回，草稿原样回到草稿列表；「修改」就是取回后打开撰写窗口，不新增状态。SMTP 暂时失败后等待重试的条目仍在排队，仍列在「已排定」里、仍能取消。开始发送以后的状态（发送中、待核实、失败）回到发件箱里，按 [0006](0006-send-at-most-once.md) 处理。
- **只由用户在界面里排定。** 新方法 `Service.SendLater` 放进 `rpcbind` 的 `uiOnly`，只有 Godwit 自己的界面（`RoleUI`）能调：
  - 插件和 Wit 本来就不能发送（[0003](0003-no-extension-can-send.md)），也没有任何排定的工具或权限。
  - `godwit mcp` 只能通过 `RequestMCPSend` 请求发送，受「通过 MCP 发送」设置约束（[0023](0023-mcp-send-setting.md)）；`mcp` 角色的白名单不变，不能排定，也就绕不开这个设置。
  - `full` 角色代表用户自己的程序，它们可以在自己选的时间调用 `Send`，不需要 Godwit 替它们保存一个以后才外发的状态。不开放给 `full`，被盗用的 `full` 令牌就不能留下一封几天后才发出、用户当时看不到的邮件。
- **审计写明是排定的。** `SendLater` 在写入条目的同一个事务里写一行审计：工具 `SendLater`，目标是草稿，`reason` 为 `scheduled for <UTC 时间>`。来源取调用上下文（界面为 `ui`）；进程内没有来源的调用也按 `ui` 记，因为只有界面能调到它。被检查拦下、没有入队的调用不留行。

## Considered Options

- **新开一个「排定」表或放进 `ops`**：要么再写一套发送、重试和恢复，要么让发送绕过发件箱的状态机，都会在至多一次上留下第二条路。发件箱已经有「最早发送时间」，只差一个标记。
- **到点时再运行 `message.beforeSend`**：插件可能在这期间变化，到点检查更新鲜；但警告没有人回答，只能像规则那样把警告当失败，用户回来看到的是一封没发出的邮件；阻止的结果也一样。排定时检查、让用户当场处理，更符合「发送永远由用户决定」。
- **开放给 `full`**：和 `Send` 对称，但多出一种由程序留下、以后无人值守外发的状态，按 [0003](0003-no-extension-can-send.md) 要和外发一样确认；目前没有程序需要它，以后有需要再单独决定，并照 AGENTS.md 加审计断言。
- **在服务器上排定**（SMTP 的 `FUTURERELEASE` 扩展，RFC 4865，JMAP 提交可以带同样的参数；Gmail 网页版的定时发送）：Godwit 关着也能按时发，但支持的服务商很少，取消和修改要另走一套协议，发出的时机也不再由发件箱掌握；以后可以作为某些账户的增强。

## Consequences

- `outbox` 新增 `send_at`；`OutboxItem.SendAt` 为零表示普通发送。主窗口把「排队且 `SendAt` 非零」的条目列在「已排定」而不是发件箱里，也不给它们弹「撤销」提示。
- 撰写窗口的 `ComposePage.Send` 多一个 `at` 参数（unix 毫秒，0 表示现在）。阅读区操作行上的「稍后发送…」不在这次范围内（#671）。
- 排定的邮件在发出前占着它的草稿：草稿列表里看不到它，要改先在「已排定」里点「修改」。
