# 标签可按账户同步成 IMAP 关键字

别的客户端、脚本和分拣邮件的 agent 用 IMAP 关键字给邮件打标记，Godwit 以前看不到；Godwit 的标签也只在本地，它们看不到。现在每个账户有一个开关「将标签同步为 IMAP 关键词」，默认关闭。打开后，这个账户的标签和服务器上的关键字互相跟随。

这份 ADR 修订 [0014](0014-labels-local-manual-wins.md)：标签默认仍只存在本地，打开开关的账户例外。手动优先不变。

- **关键字就是 slug。** 不是系统标记（`\Seen`）、不以 `$` 开头、也不是垃圾邮件标记的关键字，小写后就是标签的 slug。没有这个 slug 的标签就新建一个；名字被占用时加「 (imap)」，这个名字也被占用就不建。导入的记录来源为 `imap`。
- **服务器到本地。** 每轮同步后、以及开关刚打开时导入。关键字被去掉，来源为 `imap` 的标签随之去掉；手动、规则和模型打的标签不被导入改动。新邮件因关键字得到标签时，像模型打的一样触发标签规则。
- **本地到服务器。** 用户手动打上或去掉标签时，经现有的标记操作队列推送关键字。删除标签时先从服务器去掉它的关键字，否则下轮同步会把标签建回来。推送失败只记日志，标签照样生效。
- **用户新建的标签不同步。** 它们的 slug 是 `u` 加本地 id，在每台设备上指向不同的标签，作为关键字会被别的设备认错。要同步它们，需要先有跨设备稳定的 slug。
- **关闭只停止同步。** 已导入的标签和服务器上已有的关键字都保留。

## Considered Options

- **全局开关**：服务器是否支持自定义关键字、要不要和别的工具共享，都因账户而异。
- **默认打开**：会改变已有用户的行为，把原本只在本地的分类写到服务器。
- **按 `PERMANENTFLAGS` 是否含 `\*` 自动判断**：同步只用只读 SELECT，拿不到可写时的 `PERMANENTFLAGS`。不支持的服务器上推送的关键字不会留下，标签仍在本地，后果有限。

## Consequences

- 打开开关的账户，手动打标签会写入用户自己的 IMAP 服务器，不经过新的审批。这和已读、星标的同步是同一条路径，不涉及新的主机。开关只在设置界面和用户自己的程序（`UpdateAccount`，`full`）里能改，Wit、插件和 `godwit mcp` 改不了。
- 每轮同步都会读一遍账户里带标记的邮件。邮件很多时再改成只处理本轮标记变了的邮件。
