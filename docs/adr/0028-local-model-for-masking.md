# 脱敏可以用识别模型找人名和地址：AstrLink Guard，纯 Go 推理，Mac 上走 CoreML

[0025](0025-mask-at-cloud-egress.md) 的规则只能按格式找值，邮件正文里的人名、签名档里的地址、没有 `+` 的外国电话、前面没写「密码」的密码都找不到。参照 [magpie](https://github.com/yetone/magpie)（`internal/pii`），**脱敏**加一个可选的**识别模型**（见 GLOSSARY）：[AstrLink Guard](https://huggingface.co/QuantumNous/astrlink-guard)（Apache-2.0），一个 12 层 MiniLM 的 int8 token 分类器，支持中英文，大小 39 MB。推理代码从 magpie 移植（MIT），在 Go 里运行，不用 cgo；Mac 上通过 Swift 桥调用 CoreML。0025 当初不做 NER 的理由是「ONNX 需要 cgo」，现在不成立了。

- **开关**：默认关闭，在设置里打开。打开时才下载，下载完成并校验通过后开关才算打开；下载失败或被取消时，开关弹回关闭并显示原因，已下载的部分保留，下次续传。打开识别模型时，同时打开**人名**类别；关掉识别模型时，人名保持当前状态，不跟着关。
- **下载**：从 Hugging Face 下载固定 revision 的三个文件，按 sha256 校验，失败时自动改用 hf-mirror，走系统代理。文件放在数据目录的 `cache/` 下：丢了可以重新下载，不跟数据目录迁移。识别模型开着但文件不见了（缓存被清）时，后台自动重新下载。
- **标签和类别**：照 magpie 的映射，只是丢掉日期和链接（链接归规则的 LINK）。
  - 人名 → **人名**
  - 地址 → 新类别**地址**
  - 账号（用户名、银行账号） → 新类别**账号**
  - 电话 → **电话**
  - 邮箱 → **邮箱**
  - 密钥 → **密钥**

  地址和账号只有识别模型会找到，默认开启：识别模型关着时它们什么也不做。
- **阈值**：固定 0.8，即发布者的默认值，不给设置项。和发布者 fp32 模型在 0.8 时的结果对照，两个后端也都是在 0.8 时多出的和漏掉的最接近，不需要分开定。
- **读哪些文本**：和规则一样，包括系统提示、用户输入、邮件、工具结果和历史，只排除工具定义。后台功能（自动标签、自动总结）同样要过识别模型，因为脱敏在出口处进行，不分前台后台。
- **合并**：用户的规则和词最先处理。识别模型的结果和内置规则的结果重叠时，以规则为准，因为规则的类别和边界更准（例如邮箱只遮用户名、保留域名）。
- **已知值表**：识别模型找到的值记进全局已知值表，之后在任何文本里按原文匹配，和现在用显示名找人名一样；沿用 `shortName` 的长度下限，白名单可以排除。账号除外：它只在识别模型找到它的那段文本里遮，因为品牌名和项目名（`Godwit`、`magpie`）常被当成账号，进了表就会处处被遮。关掉识别模型后，它记下的值立即不再遮，已发出的占位符照样回填。
- **误报过滤**：识别模型的结果先过一层过滤，再交给类别开关：
  - 密钥至少 8 个字符，且不是单一符号（和规则对密钥的长度要求一致）；
  - 3、6、8 位的纯十六进制不当密钥（多半是颜色值或短哈希，验证码仍归规则的 CODE）。

  以后每加一条过滤，`core/ai/mask/guard/testdata/eval.json` 里都要有对应的样例，再拿真实邮件抽样核对。
- **推理**：
  - **所有平台**：纯 Go（`core/ai/mask/guard`），最多用一半 CPU 核、不超过 4 个。
  - **Mac**：用 CoreML（`native/guardcoreml`）。它和 `native/systemtranslate` 一样，是一个 Swift dylib，Go 用 purego 加载，所以 [0001](0001-pure-go-no-cgo.md) 不变。CoreML 程序由下载的模型权重在本机生成，第一次使用时编译一次。dylib 缺失或 CoreML 打不开、推理失败时，退回纯 Go，这不算出错。
- **缓存**：按「文本哈希 + 模型 revision + 后端」缓存在内存里，不写进数据库，和占位符表一样（0025）。
- **出错时只用规则**：识别模型开着，但文件缺失、加载失败或推理出错时，这次请求只用规则脱敏，照常发出；出错原因只在设置里识别模型的开关旁显示，不打断前台功能。这是 0025「出错就不发」的一个例外：识别模型是规则之外的加强，失败时退回到 0025 本来的保护水平。
- **可见性**：脱敏记录里每条命中标出来源，是规则还是识别模型，用户能看出误报从哪来，再决定要不要加白名单。

## Considered Options

- **OpenAI Privacy Filter**（magpie 的另一个模型）：1.6 GB，要下载原生程序 `pf-serve`（ggml），作为单独的进程运行。它多遮的主要是代码里的值，邮件用不上。
- **用 cgo 调 CoreML**（magpie 的做法）：违反 0001。Swift 桥只需要导出 6 个 C 函数，Godwit 已经有现成的做法。
- **用 purego/objc 直接发 ObjC 消息**（像 `notify_darwin.go`）：不用多一个 dylib，但 `MLMultiArray`、`NSError`、feature provider 这些对象要一个个手动处理，容易出错。
- **ONNX Runtime**：每个平台要带一个约 20 MB 的动态库。这个模型只有一个网络，手写一个 Go 实现就够了；magpie 说它和 ONNX Runtime 跑 int8 模型的结果一致（我们没有核对过）。
- **Apple NaturalLanguage（`NLTagger` 的人名类型）**：不用下载，但只有 Mac 能用，只能找人名、地名、机构名，找不了地址和电话。没有评测过。
- **随 App 打包**：可以离线使用，但不用 AI 的用户也要多装 39 MB。
- **默认开启**（magpie）：每个用户都要下载 39 MB；在 Windows 和 Linux 上，每封邮件要花几百毫秒 CPU。用户没有要求的东西不该默认就做（[0010](0010-ai-off-by-default.md) 的精神）。
- **识别模型出错时整个请求失败**（0025 的做法）：更安全，但识别模型的文件被清掉或推理出错时，Wit、总结、翻译会全部停摆，而规则本身还在正常工作。
- **识别模型的人名单独一个类别**：可以只用识别模型、不用显示名匹配，但对用户来说人名就是人名，不该因为来源不同就分成两个开关。
- **账号归「证件与金融号码」**：真实邮件里识别模型标出的账号大多是用户名，不是金融号码。
- **阈值给用户调**（magpie）：评测已经给出合适的值，误报用白名单处理。
- **把模型结果存进数据库**：重启后不用重跑，但删掉的邮件里找到的值会一直留着，还要另做清理，和 0025 不把占位符表存进数据库的理由相同。

## Consequences

- **速度**（M5 Max，最近 300 封真实邮件，中位数 579 token）：
  - **纯 Go（4 核）**：每封 p50 249 ms、p99 2.3 s，300 封共 95 s。
  - **CoreML**：每封 p50 4 ms、p99 54 ms，300 封共 2.1 s，计算计划把模型大部分放在 GPU 上。
  - 在 Windows 和 Linux 上，后台功能（自动标签）大批处理邮件时会占满给模型的那几个核。
- **同一封邮件，Mac 和其他平台遮的会不完全一样**：两个后端都是 int8 权重的近似，分数在阈值附近会浮动。用发布者的 fp32 模型（ONNX Runtime）在 336 段文本上对照，fp32 在 0.8 时找到 448 个片段：
  - **CoreML（fp16）**：相同 426 个，多出 22 个，漏掉 22 个。
  - **纯 Go（int8 计算）**：相同 408 个，多出 44 个，漏掉 40 个。
  - CoreML 更接近原版，偏差约是纯 Go 的一半。
- **效果**：在 36 封标注邮件上（53 个该遮，129 个不该遮）：
  - **只用模型**：fp32 遮住 48 个，纯 Go 50 个，CoreML 47 个，误遮都是 2 个。纯 Go 多遮的 `(415) 555-0132` 和 "Joe"，fp32 自己也没找到，算是近似误差碰巧对了。
  - **规则加模型**：纯 Go 遮住 53 个，CoreML 51 个。
  - **只用规则**：遮住 9 个。
  - 真实邮件里，账号和密钥两类可疑的命中最多：账号里有品牌名、项目名和促销码，密钥里有单个符号、极短的串和颜色值。上面的过滤和「账号不进已知值表」就是针对它们定的。
- **评测怎么跑**：标注邮件评测和 fp32 对照都是 `core/ai/mask/guard` 里带环境变量开关的测试，没设变量时跳过。fp32 对照分两步：第一次运行把每个窗口的 token 写出来，用 ONNX Runtime 算出 logits 之后再运行一次，才做比较。
- **要维护的东西**：
  - 移植来的 amd64/arm64 汇编内核。
  - CoreML 程序 `coreml.mlmodel`，换模型 revision 时要用 `coreml_gen.py` 重新生成。
  - 新依赖 `clipperhouse/uax29`，分词时切分字符用。
- **设置里的说明**：0025 里「首版不做 NER，设置里如实说明」那段文案要改；识别模型的局限要照实写：误报、只支持中英文、截图里的文字不处理。
- **出错时少遮**：识别模型出错期间，人名、地址、账号会原样发出，而用户只有打开设置才看得到原因。
- **后台开销**：在 Windows 和 Linux 上，自动标签每封新邮件要多花几百毫秒 CPU。
- **prompt cache**：打开或关闭识别模型、换后端或换模型 revision 后，会失效一次。
