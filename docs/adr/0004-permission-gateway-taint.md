# 统一权限网关和持久的来源标记

插件、MCP 和 Wit 的所有工具调用和外发，都经过宿主的同一个网关，按「调用来源 + 数据范围 + 外发目的地」判断是否放行，并记审计日志。外发在**实际发出请求的那一刻**检查：如果这条调用链读过邮件内容，就要用户审批，审批卡片上显示目的域名。

来源标记是持久的：一个对话读过邮件后，它此后的每次运行（包括重启后）都按「已读邮件」处理；插件一旦收到过邮件内容（`holds_mail`），之后的 Action / Tool 外发都按拥有 `mail:read` 处理，直到卸载。不做成按单次调用判断，是因为插件常驻内存、能跨调用保存数据，单次调用干净不代表它手上没有邮件。

## Consequences

- 邮件内容交给模型时一律标为不可信数据；写操作工具一律需要审批。审批绑定调用 ID、最终参数和目标对象的版本，参数或对象变了审批就失效。
- 审批只执行一次：每个待审批调用持久化为「待审批 → 已批准 → 执行中 → 已完成 / 已拒绝」，带幂等键；崩溃后停在「执行中」的调用，先核对是否已经生效。
- MCP 工具默认每次都审批，用户可以把单个工具标为「信任的只读工具」（工具定义一变就失效）；`readOnlyHint` 不作为安全依据。
- 插件翻译（`KindTranslate`）是例外：安装时用户已确认会把邮件发往声明的主机，翻译时不再逐次审批。
