# 智能邮箱：规则放入，处理后离开，内置「今日」

用户要的是该回的别漏、等别人回的到时催、要办的事别被收件箱淹没（[#472](https://github.com/godwit-email/godwit/issues/472)）。Godwit 不为此新增「任务」，邮件本身就是要处理的事；我们新增**智能邮箱**：侧栏里一个由规则放入会话的地方。它以用户少动手为前提：系统自动放入，用户只在系统判断错了或漏了时才动手。

**进入。** 规则新增一个动作「放入智能邮箱」，规则的其余部分不变。一个智能邮箱可以由多条规则放入，放入的单位是会话，不是单封邮件；默认跨账户，规则可以限定账户。规则条件新增会话状态（**轮到我**、**等对方回复**）和等待时间（已等 N 天），用户自己的规则也能写，例如「客户 3 天没回我」，不存在只给内置功能用的条件。

**离开。** 每个智能邮箱有一个开关「处理后自动离开」，默认打开。处理指我回复了或归档了；关闭后邮箱可用来留档，例如「发票汇总」。删除的邮件总是离开。这一点不写成规则：规则在事件发生时执行一次，离开判断的是会话此刻的状态。把早已回复的旧会话放入时不会再有「我回复了」这个事件，从归档移回收件箱的会话也需要回到邮箱，事件做不到这两点。

**完成。** 用户对不需要回复的会话按「完成」，一键、不用确认、可以撤销。完成就是手动移出，不是另一种状态，也不移动服务器上的邮件、不改已读。同一会话之后有符合规则的新邮件时会被再次放入；对方回信本身也会让会话回到「轮到我」。已读不算处理：读过不等于办完。

**「今日」。** 每个用户默认有一个内置的智能邮箱「今日」，分「轮到我」和「该催了」两组，每行写明为什么在这里。它和用户自己建的智能邮箱没有区别：规则可见、完全可编辑，也可以删除。同时它也是一个规则模板，用于恢复或再建一份。用户没改过的「今日」随版本更新；改过的不动，只提示有新规则可以添加。第一次运行只处理最近 7 天的邮件。默认规则是：真人直接发给我且我没回（抄送、群发、订阅和通知不算）；我发出后 3 天对方没回。

**这修订了 [0030](0030-mail-rules.md) 的「不自动创建任何规则」**，只为「今日」的默认规则破例。理由是这些规则没有副作用：只放入智能邮箱，不移动邮件、不改状态、不外发、不调用模型，而且用户看得见、改得了、删得掉。其他规则仍然不自动创建。规则跳过已发送邮件的限制也要放宽，否则判断不了「等对方回复」；转发和 AI 动作仍然不因已发送邮件或旧邮件触发。这也修订了 [0014](0014-labels-local-manual-wins.md) 的「不给已发送分类」：回复状态不是标签，不写入 `message_labels`，也不向模型发送邮件。

**AI 不是前提。** 按 [0010](0010-ai-off-by-default.md)，AI 关闭时上面全部照常工作。AI 打开时，用户可以用自动标签作为规则的触发放入智能邮箱，也可以选用「信里有要办的事」这条规则，每行带一句要做什么和原文依据；这条规则在回复状态验证之后再做。AI 只决定放入，不判定完成，也不代替用户回信。

**外发。** 这个决定本身不造成外发：放入和离开都只写本机状态，不产生之后会自动发信或请求某个主机的持久状态（[0003](0003-no-extension-can-send.md)）。AI 规则发给用户配置的模型服务，照常脱敏（[0025](0025-mask-at-cloud-egress.md)）。Wit 只能通过 `propose_rule` 提议这类规则，由用户保存。

## Considered Options

- **纯实时查询（Apple Mail 的智能邮箱）**：改条件就覆盖历史邮件，没有放入和离开的状态。但用户得先想好条件，而且表达不了「这件事我处理完了」。
- **保存搜索作为主入口**：不用学规则，但搜索不该是主流程，也同样表达不了完成。
- **只用现有的「打标签」动作，标签视图就是入口**：改动最小。但标签回答「这是什么」，不表达「接下来做什么」；所有标签都会被自动标签逐封判断，AI 会把邮件误放进去；标签还按单封邮件工作，而用户关心的是会话。
- **隐藏标签存放成员关系**：省下新表，但标签列表、计数、分类器都要加例外，长期更贵。所以成员关系按会话单独保存。
- **新增「任务」实体**：能表达不需要回复的事，但用户要在邮件之外多维护一份清单，这正是最该避免的。
- **纯手动跟进，或自动判断只作建议、确认后才进入**：准确，但逐条确认还是手动，没有解决「太依赖手动」。选了直接放入，靠严格的默认条件、写明原因和一键完成来保持可信。
- **「今日」只做模板**：不用破例，但用户要先知道它、再点一下才有，默认体验等于没有。
- **「今日」只读，或只能调参数**：默认逻辑容易升级，但用户看到的是一个不能改的特例，和「规则是一套」相矛盾。
- **离开条件逐个邮箱配置，或写成规则**：更灵活，但放入和离开就成了两套规则要配，理由见上文。第一版只有一个开关；确有需要时再加「移出智能邮箱」动作。

## Consequences

- 「轮到我」的准确率决定这个功能的成败。上线前要先用真实邮箱测一遍：现在每个用户升级后都会直接看到「今日」，误报太多它就没人看了。
- 「我发的」要能认出别名和多身份；已发送邮件同步不完整时不能误判成「轮到我」。
- AI 关闭时过滤通知和订阅不能靠自动标签，要有基于邮件头的判断。
- 等待时间和状态变化也要能让规则生效，不能只等新邮件事件；规则的「一封邮件只跑一次」要和按会话放入、新邮件再次放入对得上。
- 新增的条件要守住 0030 的白名单，别让条件长成一门语言。
- 规则的放入动作要写进 `propose_rule` 的描述和 `askTools` 的注释；`core.Service` 的新方法按 AGENTS.md 进 `full`（`rpcbind/testdata/full_methods.txt`）。
- 第一版不覆盖不需要回复的事，比如周五前付款，要等提醒或 AI 规则，所以它不算完整交付 #472。提醒（给会话设一个时间，到点通知并放入「今日」）紧接其后，已经改过「今日」的用户需要手动添加这条规则。桌面应用关着时提醒不会准点响，下次启动时补上。
- 第一版不做：保存搜索、AI 提取、提醒、任务实体、`godwit mcp` 的新方法、与外部待办应用同步。
- 这个决定接受后，要在 0030、0014 里加上指向这里的修订说明。
