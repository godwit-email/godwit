# 插件目录用 ed25519 签名，发布到 R2

可信插件名单是一个 `registry.json`，由独立仓库 `godwit-email/plugins` 维护，CI 用 ed25519 私钥签名后，和 `registry.json.sig` 一起上传到 R2，应用从 `https://dl.godwit.email/plugins/registry.json` 读取。公钥是 `core` 里的常量（和更新器的密钥分开）。名单来源能否验证不依赖谁控制 CDN 或反代，Go 标准库就能验签，不加依赖。格式用 JSON 不用 YAML，因为标准库没有 YAML。

名单里的信息全部来自名单本身：**绝不先加载插件文件再从里面读名称或能力来展示**。下载的产物 sha256 和名单不符时直接丢弃报错，**没有「仍然继续」**。名单刷新失败时保留旧缓存；`updated` 早于缓存的名单被拒，防止回滚。

## Consequences

- 原生插件和脚本插件都在同一个名单里。对原生插件，「已审核」意味着这个文件可以加载，首装确认一次风险后直接启用；对脚本插件，审核**不替代**用户对权限的授权，安装后仍显示权限卡片，用户点「允许」才启用。
- `trust` 列记录授权来源：`listed`（安装时命中名单）或 `user`（用户看过风险提示后自己授权）。名单删掉某个 release 后，已装的 `listed` 插件会被 `trust_revoked` 停用。
- 发布产物是裸动态库（或单个 `.js`），不打 zip 包：没有 zip-slip，名单里的哈希就是那一个文件的哈希。
