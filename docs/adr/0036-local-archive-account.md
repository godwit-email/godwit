# 本地 .eml 导入到「本地归档」账户，原文件就是邮件本身

有的用户邮箱空间有限，习惯把邮件下载成 .eml 后删掉服务器上的副本（#509）。这些旧邮件已经不在服务器上，同步拿不回来；他们希望在 Godwit 里离线查看和搜索，不上传。

导入的邮件放进一种新账户：**本地归档**。它没有 IMAP、SMTP，不同步，也不能用来发信。用户选择一批 .eml 文件或一个文件夹，Godwit 把每个文件复制到数据目录的 `archive/` 下，这份副本就是这封邮件的原件：`GetRawMessage` 读它，附件从它解析，不进附件缓存，也不参与缓存淘汰。邮件头、正文和全文索引照常用 `core/mail` 解析，写进 `messages`、`message_locations` 和 `messages_fts`，所以列表、会话、搜索、标签和联系人整理都不用为它另写一套。

- **不算收到新邮件。** 导入不写 `message.received`，不触发规则（[0030](0030-mail-rules.md)）、插件和 AI 分类。一次导入几千封旧邮件，如果当成新邮件，会让带外发动作的规则把旧邮件发出去。用户想对它们跑规则，用 0030 里已有的「对现有符合条件的邮件执行一次」，外发和 AI 动作照旧不对旧邮件执行。
- **位置只在本地。** 本地归档的邮件只有位置，没有服务器位置；它们的文件夹是用户在这个账户里建的本地文件夹，不对应任何服务器。所以 0005 里「uid 为空 = 还没推送」的含义只适用于有服务器的账户；同步、操作队列和清除不处理本地归档账户。
- **删除是真删。** 修订 [0005](0005-local-first-identity-vs-location.md) 的「Service 不提供硬删除」：本地归档里没有服务器替用户留底，删除先进废纸篓，清空废纸篓时连同 `archive/` 里的原件一起删掉。其他账户不变。
- **重复导入跳过。** 同一账户里按原件的 SHA-256 判重，同一个文件导入两次只算一封。Message-ID 不决定身份（同 [0034](0034-message-and-its-locations.md)），Message-ID 相同、内容不同的两封各算一封。
- **不外发。** 导入只读用户选的本地文件、只写本机数据目录，不连接任何主机。导入是用户在界面上发起的操作，新增的 Service 方法进 `full`，不进 `audit`；Wit、插件和 `godwit mcp` 不提供导入。

## Considered Options

- **导入到现有 IMAP 账户的某个文件夹**：省一种账户，但没有服务器位置的邮件会被同步和操作队列当成待推送的移动，最后要么 APPEND 到服务器（用户正是不想上传），要么标为冲突；附件按需从服务器下载，也拿不到。
- **只存解析结果、不留原文件**：省空间，但导出 .eml（0030 的 `eml` 动作）、转发带原附件、以后改进解析器重新解析都需要原件。附件缓存会被淘汰，不能当原件存放处。
- **导入后 APPEND 到服务器**：是另一个需求（迁移邮件），以后有人要再做，和本地归档不冲突。
- **mbox、Maildir**：没人提，先不做；以后可以拆成多个 .eml 走同一条导入路径。

## Consequences

- 账户模型里默认有服务器的地方（连接检查、同步调度、清除策略、发件身份、退订、MCP 发送）都要跳过本地归档账户。
- 本地归档账户的邮件不能用它自己的身份回复或转发，改用默认的有 SMTP 的账户起草，用户可以在写信窗口里换。
- 本地归档没有用户自己的地址（只有占位地址），按主题归并会把用户的收件地址当成共同参与者，所以它的邮件只按 References、In-Reply-To 和 Message-ID 归并会话，不按主题兜底。
- 数据目录的备份和占用统计要算上 `archive/`；删除整个本地归档账户会删除其中所有原件，界面要明确说出来。
