# 发给云端的文本一律脱敏，在 Go 的出口处进行

邮件里满是电话、证件号、验证码和重置密码链接，而 Wit、总结、翻译、自动标签会把它们原样发给云端模型。参照 [magpie](https://github.com/yetone/magpie) 的隐私脱敏，Godwit 对发往云端服务的**全部文本**做**脱敏**（见 GLOSSARY）：先换成占位符再发出，模型输出里的占位符在用户看到、工具执行或邮件发出之前换回原值。脱敏点放在 Go 的出口，而不是拼 prompt 的地方，这样任何功能都绕不过去。

- **范围**：系统提示、用户输入、草稿（含引用的原文）、工具结果和历史都要处理。云端服务指模型服务（包括 localhost、订阅登录和插件模型）和翻译插件。只有 Apple Intelligence 和系统翻译算本机，不脱敏。用 BaseURL 判断不可靠：Apple 的地址本身就是 loopback，而 localhost 上可能只是一个转发到云端的代理。
- **类别**：密钥、证件与金融号码（带校验位）、验证码与一次性链接（复用 `mail.SignInCode`、`EmphasizedCode`、`ActionLink`）、电话（中国大陆手机和座机，以及带 `+` 的国际号码）、邮箱（只遮用户名，保留域名，因为标签和分拣要靠域名）、人名（取 From/To/Cc 的显示名，再到正文里按原文匹配）。总开关默认开启，老用户升级后同样开启；人名默认关闭，因为显示名常常是品牌名。
- **用户配置**：每个类别可以选**遮住**、**仅警告**（原样发送，只记下来）或**拦截**（整次请求不发：前台功能报错并指出命中的类别，后台功能跳过这封邮件，Wit 停在这一步）。另有自定义词、自定义正则（最多 32 条，保存时校验）、白名单和实时预览，预览不保存任何内容。
- **占位符**：格式为 `{{KIND_` 加 12 位 base32 `}}`，即用本机密钥对「类别 + 值」做 HMAC，取 60 位，同一个值永远得到同一个占位符，prompt cache 因此不会失效。密钥存在数据库里，随数据目录迁移；数据库本来就存着邮件明文，单独保护密钥没有意义。
- **占位符表**：全局一张，只放在内存里。重启后，用存储的真值（用户提问、工具读出的邮件）重新计算，就能得到同样的占位符。
- **可见性**：设置里有脱敏记录，每次请求记类别、首字符和长度，保留 30 天，不记原值。Wit 的轮次上标「已脱敏 N 处」，「仅警告」的命中也在这里提示。

## 脱敏点与回填点

一个点覆盖不了全部，需要三个脱敏点：

- **M1，pi 的 `host.fetch`**（`core/ai/pi/pi.go`）：在 `http.NewRequest` **之前**通过 Hooks 回调完成（`pi` 包不能依赖 `ai`）。它覆盖 Wit 的每一步和重试、总结、即时回复、正文翻译、撰写辅助、压缩、插件的 `llm.complete`，以及所有 HTTP 判断模型。插件模型的 `prepareRequest` 在它之后执行，拿到的已经是脱敏后的文本。要不要脱敏由 `ResolvedModel` 上一个只在 Apple 分支设置的标记决定。
- **M2，插件判断模型**：在 `pluginModelJudge.dispatch` 处理，它不走 HTTP。
- **M3，翻译插件**：在 `callTranslator` 一处完成脱敏和回填，四个调用点都能覆盖。

回填对所有模型都执行，包括 Apple，因为对话中途可以切换模型。回填点有：

- 流式文本和推理：半个占位符先扣住，在工具事件和结束事件之前补发。
- 工具参数（Args hook）：认不出的占位符直接拒绝执行，和 `toolArgs` 拒绝认不出的链接引用一样。
- 被拒绝的调用、中断、`display` 和对话展示：Text、Reasoning、`Calls[].Args`，以及 Results 和错误。工具参数解析失败时，pi-ai 会把原始参数回显进工具结果。
- 发送前的检查：主题、正文、To/Cc/Bcc/Reply-To 里还有占位符就拒绝发送；信封收件人在回填之后再计算。

## Considered Options

- **拼 prompt 时脱敏**（像现在的链接引用 `linkRefs`）：会漏掉 pi-agent-core 校验失败时回显的参数、审批结果、Apple 写下后来又发给云端的历史，还要把「是否云端」一路传进 `mailContext`。
- **localhost 或局域网算本机，或者每个服务一个「不脱敏」开关**（magpie）：localhost 上可能是 LiteLLM 这类转发代理。
- **每个对话一张表，只回填本对话发出过的占位符**：能挡住「被攻破的模型重放别处见过的占位符」。最后选了全局表，这个风险靠写工具的审批来兜底：审批卡片显示的是回填后的真值。
- **占位符表存进数据库**：旧对话总能完整回填，但删掉的邮件里的号码会一直留在表里，还要另做清理。
- **NER 识别正文里的人名和地址**：ONNX 需要 cgo，违反 [0001](0001-pure-go-no-cgo.md)；magpie 自己也记录了模型在真实流量上误报居多。首版不做，设置里如实说明。
- **总开关默认关闭**（magpie）：大多数用户不会主动打开。脱敏不会多发出任何东西，所以默认开启不违背 [0010](0010-ai-off-by-default.md)。

## Consequences

- **出错就不发**：规则异常或识别崩溃时，这次请求直接失败。
- **重试会读回原文**：`strings.NewReader` 让 net/http 的 `GetBody` 返回原始请求体，连接复用失败或 HTTP/2 GOAWAY 时重试会用它重建请求。所以 M1 必须在构造请求之前完成，不能只在 RoundTripper 里替换 `Body`。插件模型客户端断言自己的 Transport 是 `*pluginModelTransport`，所以也不能把它包起来。
- **JSON 遍历必须了解协议**：只处理字符串值，系统提示（Anthropic 的 `system`、Responses 的 `instructions`）也要处理。id、签名和 `encrypted_content` 跳过；工具定义只处理 `description`。工具输出是 JSON 套在 JSON 字符串里的，要在去掉转义后的文本上识别，HTML 转义过的值同理。
- **回填要宽容但只认自己生成的**：只按哈希部分匹配，容忍大小写和括号的变形，因为翻译时模型可能把 `EMAIL` 也翻译掉。不在表里的占位符保留原样。邮件里本来就有的同样式文本，先像 `defuseRefs` 那样拆掉。回填放在解析 JSON 和 HTML 之后，否则值里带 `"` 或 `<` 会被破坏。
- **碰撞**：60 位的哈希在全局表里也基本不会碰撞，另外再做碰撞检查。
- **判断模型**：选项值脱敏后发出，答案先回填再校验（`ValidateAnswers`）。
- **正文翻译**：先脱敏再切段，否则被切开的值识别不出来。
- **prompt cache**：改动类别、自定义词或密钥后会失效一次。
- **旧对话**：开启前存下的 Anthropic 带签名的思考块和 Responses 的加密推理改不了，会保留并原样发回；内存里的表重建不出来的值（只出现在系统提示里的，或后来删掉的自定义词）会显示成占位符原文。
- **不在范围内**：`godwit mcp` 和本机 API 交给外部 agent 的邮件、插件自己通过 `net.fetch` 调用的模型，都不经过脱敏，设置说明里要写清楚。现有的来源标记和审批（[0004](0004-permission-gateway-taint.md)）不变，日志里的**抹除**（`Redact`）也不变。
- 不做 magpie 的「保形假值」模式。
