# 跨设备同步：密文放在用户自己的存储里，同步密钥只在用户的设备上

换一台设备，今天要把账户一个一个重新添加（#652 的第 3 项）；账户导出与导入（#739、#740）不带凭据，每个账户还要重新授权一次。用户要的是像 Apple 生态那样自动。Godwit 不运营服务，也没有账号体系，所以这份数据只能放在用户自己已有的存储里，而密钥不能交给那个存储。

我们定下**跨设备同步**（见 GLOSSARY）：账户、设置与凭据逐条用**同步密钥**加密，只把密文放到用户选的载体上；同步密钥只存在于用户自己的设备上。本 ADR 只是设计，不含实现。

## 决定

- **同步什么**：账户（协议后端与服务器、登录名、发件人名称、签名、同步范围）、设置、凭据（密码、OAuth 令牌）。邮件不在其中，它在邮件服务器上。本地归档不同步。规则、标签、视图是否加入，另行决定。
- **载体由用户选一种**，同一时间只用一种：
  - **iCloud**（CloudKit 私有数据库）：只适用于全部设备都是 Apple 设备的用户。
  - **WebDAV 或 S3**：用户自己的。有 Windows 或 Linux 设备的用户，所有设备（含 Mac）都连同一个。
- **一种密文格式，两种载体**。记录在离开设备之前加密，载体只看得到密文。
- **同步密钥怎么到一台新设备**：
  - iCloud：同步密钥是 iCloud 钥匙串里一条可同步的条目，新设备登录同一个 Apple 账号就有了，用户什么都不用做。
  - WebDAV/S3：**设备配对**。旧设备显示二维码或一次性码，新设备扫一下或输一次。第一次打开跨设备同步时给用户一个**恢复码**，全部设备都丢了时靠它恢复；恢复码也丢了，只能重新添加账户。
- **冲突**：逐条记录，后写的赢。
- **载体的访问凭据**（WebDAV/S3 的地址、账号、密钥）每台设备各存一份在本机 keychain，不参与同步，新设备要填一次。
- **凭据落地**：同步进来的邮箱凭据写进本机 keychain，之后和今天一样从本机读，不是每次去载体取。
- **由后端进程执行**（[0038](0038-backend-process-owns-the-engine.md)），界面不在时照常同步。
- **默认关闭**。在此之前凭据从不离开本机，这是本 ADR 改变的事。打开时：WebDAV/S3 要一次写明目标主机的审批，并留审计行，因为之后的上传没有用户在场；iCloud 要一次明确同意。

## Considered Options

- **只用 CloudKit 的加密字段**：实现最省。但它只有在用户自己开了「高级数据保护」时才是端到端加密，没开的用户密钥在 Apple 手里。同步密钥放 iCloud 钥匙串则对所有用户始终端到端。
- **邮箱凭据直接存成可同步的钥匙串条目**：同样端到端、全自动，但全部凭据的读写都要换成系统的钥匙串接口，而且只解决 Apple 这一边，WebDAV/S3 还要另一套。
- **口令派生密钥**：实现最简单，没有旧设备也能恢复。但每台新设备都要输口令，正是要避免的；存储方还可以离线猜口令。
- **同步密钥和数据放在一起**：新设备只填访问凭据，全自动。但存储方，或拿到访问凭据的任何人，都能读到所有邮箱的密码和令牌。
- **按平台固定载体**（Apple 用 CloudKit，其他用 WebDAV/S3）：一个既有 Mac 又有 Windows 电脑的用户，两台设备永远同步不到一起。
- **Mac 同时写两处做桥**：同一份数据有两个载体，冲突与顺序要多处理一层。
- **Windows 和 Linux 经 CloudKit Web Services 读同一个容器**：要网页登录，一次登录最长两周；开了高级数据保护的账号默认关闭网页访问，有开发者报告重新打开后仍被拒。
- **用户云盘里的一个目录**（iCloud Drive、OneDrive 之类）：不联网、不算外发，但目录级同步没有条件写，冲突只能靠时间戳猜。
- **Godwit 自建服务**：三个平台一套，还能推送。但要运营服务器和账号体系，并替用户保管邮箱凭据。
- **只同步配置，凭据每台设备重新授权**：最安全，就是账户导出与导入已经给的体验，没有回答「换设备要自动」。

## Consequences

- **macOS 构建要变**：iCloud 钥匙串和 CloudKit 都要求应用嵌入描述文件并带相应权限。同步密钥要用系统的钥匙串接口读写，现在读写凭据用的 `security` 命令行工具写不了可同步的条目；仍然不用 cgo（[0001](0001-pure-go-no-cgo.md)）。只有同步密钥这一条换接口，邮箱凭据的读写不动。
- **钥匙串的访问权按进程的主可执行文件判定**。后端进程在 `Godwit.app` 这个 bundle 里（0038）才能读到同步密钥；后端如果是包里的第二个可执行文件，它的权限安排要在真机上核实（#719）。
- **Windows 和 Linux 做不到全自动**：新设备要填一次载体的访问凭据，再配对一次。调研到的邮件客户端里，自动的要么靠 Apple 账号，要么靠厂商自己的服务器。
- **换载体是一次迁移**：从 iCloud 换到 WebDAV/S3（比如新添了一台 Windows 电脑）要重新上传，其余设备重新配对。
- **撤销一台设备**：换一把同步密钥、其余设备重新配对。丢失的那台设备本机 keychain 里仍有邮箱凭据，那得去邮件服务商那里改密码或吊销授权，跨设备同步管不到。
- **OAuth 令牌多台设备共用一份**。会轮换 refresh token 的服务商上，一台设备刷新可能让另一台手里的失效。实现时要先核实各服务商的行为，再决定是同步新令牌并重试，还是这类账户每台设备各自授权。尚未核实。
- **后写的赢会丢一边**：两台设备同时改同一个账户时，先写的那次改动没了。
- **恢复码丢失且没有其他设备时无法恢复**，没有找回。
- **这些平台结论只来自文档与开发者论坛**，没有在真实的 Developer ID 构建上验证：Developer ID 应用使用 iCloud 钥匙串与 CloudKit 的确切要求、后端进程能否收到 CloudKit 的变更推送。实现前先各做一次验证。
