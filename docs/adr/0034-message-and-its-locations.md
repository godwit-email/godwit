# 一封邮件一行，它在哪些文件夹另存一张表

Gmail 把同一封邮件同时放在收件箱、每个标签的文件夹和「所有邮件」里，每处有自己的 UID。以前每处存一行，显示时再按 Message-ID 折叠成一封（#464），但每行有自己的标记、标签和操作队列：归档会和另一行冲突（#506），另一行上排队的修改被丢掉、显示「未能应用」，已读和星标在几行之间不一致，正文和全文索引也存了几遍。

现在本地把一封邮件拆成两部分。**邮件**一行，存内容和整封共享的状态：邮件头、正文、全文索引、安全判定，以及 Gmail 跨标签共享的标记（已读、星标、已回复、关键字；`\Deleted` 不算）。它在哪些文件夹，存在另一张**位置**表里，每个（邮件，文件夹）一行，每行都有自己的**期望位置**（用户此刻是否在这个文件夹看到它）和**服务器位置**（UIDVALIDITY + UID，还没确认时为空），以及进入这个文件夹的时间（废纸篓、垃圾邮件的自动清除按它计时）。操作队列属于邮件，一封邮件只有一条队列。

这份 ADR 修订 [0005](0005-local-first-identity-vs-location.md)：身份和位置照旧分开，但期望位置和服务器位置不再是每封邮件各一个，而是每个位置各一对。它也取代 #464 在显示层折叠副本的做法，`Copies`、`CopyOf`、`Merged` 一并删除。

- **身份。** 账户支持 `X-GM-EXT-1` 时，一个 `X-GM-MSGID` 就是一封本地邮件，在账户内唯一，按不透明字符串保存。Message-ID 和 `X-GM-THRID` 不决定身份，Message-ID 只用来归并会话。
- **账户能力独立保存。** 建立账户的连接检查、修改服务器和认证成功的连接都记录账户级 `X-GM-EXT-1`，不靠缓存里是否还有 Gmail ID、也不靠 All Mail 的角色判断账户类型。升级时仅在 `gmail` provider 的当前 IMAP endpoint 为 `imap.gmail.com` 或 `imap.googlemail.com`、993 端口及 TLS 时确定回填；provider 和旧邮件的 Gmail ID 可能来自更换服务器之前，不能单独证明当前能力。其他未知老账户在归档前只探测能力，探测失败就保留原状态并报告错误，不能离线猜测普通移动语义。
- **普通 IMAP 不合并。** 用同一套表，但每封邮件始终只有一个位置：COPY 出来的两封各算一封、标记各自独立，Message-ID 相同的两封也不合并。这与此前不同：以前同一会话里 Message-ID 相同的几行在显示时折叠成一封，现在普通账户的这些副本各算一封（自己抄送自己时 INBOX 与已发送各一封）。
- **UID 消失只删位置。** 某个文件夹里的 UID 不见了，只说明邮件离开了这个文件夹；UIDVALIDITY 重置或文件夹被删，也只删掉对应的位置。只有一封邮件一个位置都不剩、没有待推送的操作、且发现这一点的那轮拉取已经扫完所有文件夹时，才删除这封邮件。在 Gmail 网页上归档或去掉标签，不会让 Godwit 删掉邮件。

## Considered Options

- **保留每处一行、继续在显示层折叠**（#464）：改动最小，但标记、标签和操作队列仍按行分开，#506 这类冲突和「未能应用」只能逐个修补。
- **每封邮件一行、只记一个位置**：把显示层的折叠直接下沉到存储，但在别的客户端归档或去掉标签时，UID 消失会被当成邮件被删，整封邮件丢失。
- **按 Message-ID 或内容合并**：不同的邮件可能共用 Message-ID 和内容，合并后标记会混在一起。只有服务器给出的 `X-GM-MSGID` 和 COPYUID 能证明两行是同一封。RFC 8474 的 `EMAILID` 以后可以用来认领，但不合并标记。

## Consequences

- 用户的操作作用于邮件，从哪个文件夹发起就移出哪个文件夹：在 Gmail 上归档只去掉收件箱，标签保留；删除隐藏所有位置、只显示在废纸篓。没有单一文件夹的视图（统一视图、搜索、标签视图）里，移动的源是收件箱位置，不在收件箱时是除「所有邮件」外所有看得到的位置。
- 移动和清除的操作记下源文件夹，推送时从记下的位置发出，不挑「任意一个」服务器位置。Gmail 归档只移出 INBOX；没有 INBOX 时不移动任何标签。All Mail 隐藏时不需要归档目标或目标 UID：`move` 的目标为空表示只移出源，撤销归档时源为空表示只加入目标，不移除其他标签。
- `X-GM-EXT-1` 不保证 `MOVE`。有 `MOVE` 且有合适的目标时保留 UID MOVE；缺少 `MOVE`，或隐藏 All Mail 的归档没有目标时，适配器通过 fork 的 `STORE ±X-GM-LABELS` 执行最小标签增删。普通移动先加目标再去源，归档只去 INBOX，Trash/Spam 通过加入系统标签触发服务器的特殊转换，不使用 COPY → `\Deleted` → EXPUNGE，也不替换整套标签。这把 #518 原定延后的标签写入收窄提前到执行已有移动意图，不增加标签编辑界面。
- 结果不确定的操作先按 UID 或 `X-GM-MSGID` 和服务器核对，不盲目重放。标签适配器每次用 `SEARCH X-GM-MSGID` 检查记下的源和目标：目标已加入只补去源，源已离开且目标已到达就完成，保留其他客户端新加的标签；源、目标都没有时明确报告冲突。失联不因重试次数而删掉或放弃未核实的 Gmail 意图。只加入目标的意图可从任何经身份核实的现存位置发出，且不会移出这个位置。
- **隐藏 All Mail 且归档将移出最后一个可见位置时**，本地立即隐藏 INBOX，服务器操作只在现有归档撤销窗口（`UndoArchiveWindow`，10 秒）结束后发出；期限存进操作 payload，重启沿用原期限，复用现有 worker 定时器。有其他服务器位置或 All Mail 可用时不增加等待。列表、会话和联系人 toast 使用同一常量，期限从 UI 发起请求前计算，不能比 Service 提交后的期限更晚；窗口内撤销取消未发出的操作，不先移出再加回。
- All Mail 不在 IMAP 可见文件夹中时，扫完这些文件夹不能证明一个已知 Gmail 对象被永久删除；保留邮件身份和内容，不保留或伪造已失效的 UID。窗口后（包括没有固定期限的规则撤销）若已无可寻址位置，撤销意图保持 pending，并通过待办错误及 SyncFailed 明确报告需显示 All Mail 或在其他客户端恢复标签；拉取仍继续，可见位置重新出现后按原 Gmail ID 认领并完成，不 APPEND 新邮件代替原对象。
- 移动返回的 COPYUID 指向另一行已有的（文件夹，UID）时，说明两行是同一封，当场合并，取代 #514 丢弃副本的做法。没有 COPYUID 的认领在 Gmail 上先按 `X-GM-MSGID` 匹配，再退回 0005 的 Message-ID + 大小。
- 「在文件夹 X」指有一个看得到的位置在 X，「不在 X」指没有任何看得到的位置在 X；未读数、会话数和联系人统计按邮件或会话计，不按位置计。[0031](0031-views.md) 里「Gmail 同一封信的多个副本算一封」由存储保证，不再靠显示折叠。
- 迁移分两步。先把每行拆成一封邮件 + 一个位置，一一对应、行为不变；Gmail 拿到 `X-GM-MSGID` 后再把同一封的几行合并，保留原来显示的那行（收件箱 > 其他 > 所有邮件，再按 id 最小），不等队列清空。合并后标记从服务器重新拉取，待推送的标记操作再叠上去；标签按来源取最高（手动 > 规则 > 自动），手动的去掉胜过手动的加上；草稿、规则运行记录、Wit 引用、附件缓存都指向保留的那封，在任一行上跑过的规则不再重跑。被合并掉的旧 ID 记进别名表，Service 所有接收邮件 ID 的入口都先经它解析。
