# 发送至多一次

SMTP 无法保证「恰好一次」，Godwit 选择**至多一次**：宁可让用户确认，也不重复发出。发件箱状态机是「排队 → 发送中 → 已发出 → 存档中 → 完成」，另有「发送待核实」「存档待核实」「失败」。服务器是否已经接受无法确定时（提交后断线、进程崩溃），标为「发送待核实」，**不自动重发**；用户只能对待核实和失败的条目选择「确认已发出 / 重新发送 / 丢弃」。

存档到已发送文件夹前，先按 Message-ID 搜索（很多服务商会自动保存已发送邮件）。`SEARCH HEADER` 是子串匹配，命中后还要取回邮件头逐字比对，已经存在就不再 APPEND。APPEND 结果不确定时同样进入「存档待核实」。

**撤销与修改只作用于确定没发出的条目**（#211）。点发送后，条目先排队 10 秒（撤销窗口），草稿挂在条目上、只读，直到邮件可能已经发出：进入「已发出」或「发送待核实」的同一次更新里删除草稿。只要条目还在「排队」，用户就能**撤销发送**；「失败」的条目可以**修改**。两者都实现为删除条目、草稿恢复，不新增状态；能否撤销由一条 CAS 判断（删除只在仍是排队时成功，认领发送也只在仍是排队时成功），所以两者恰好一方成功。发送中、已发出、待核实的条目不能撤销。升级前排队的条目没有草稿，不提供撤销和修改。

**错误按 SMTP 回复分级。** 发送在第一个被拒的收件人处停下，整封都没发出，所以拒绝总是可以安全重试或修改。服务器明确拒绝（5xx）立即转为失败，记下阶段、收件人、返回码和原文；4xx、断线、超时这类服务器接受之前的错误回到排队，按退避（1 分钟起翻倍，上限 1 小时）再试，不再有次数上限。认证失败暂停发件箱、不计次数；结果不确定仍进入「发送待核实」。

**排队过久转人工。** 认领前，排队超过 3 天（从最早发送时间算，重新发送会重新计时）的条目转为失败，原因「排队时间过长」，交给用户修改、重新发送或丢弃，而不是在离线或需要重新登录好几天后悄悄发出。
