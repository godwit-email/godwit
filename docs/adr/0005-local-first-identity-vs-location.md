# 本地优先，邮件的身份和位置分开

所有修改先写进 SQLite 和操作队列，界面立刻响应，同步模块在后台推送到服务器。Service 不暴露 IMAP UID（UIDVALIDITY 一变 UID 就全部失效），只暴露在邮件整个生命周期内不变的本地 ID。

每封邮件同时记录两个位置：**期望位置**（用户看到的文件夹，本地修改立即生效）和**服务器位置**（最后确认的文件夹 + UIDVALIDITY + UID）。拉取按服务器位置去重，所以还没推送的移动不会让源文件夹里的邮件被重复导入。

## Consequences

- 移动后服务器返回 COPYUID 时直接更新服务器位置；不返回时进入「待认领」，下次拉取目标文件夹时，只有 Message-ID 非空、且和大小一起唯一匹配的那封才会被认回；有歧义就标为冲突，按新邮件导入。
- 操作队列里每个操作都记下它针对的「文件夹 + UIDVALIDITY + UID」；推送前先核对 UIDVALIDITY，不一致的操作标为冲突、不再重放。同一封邮件的操作按顺序执行。
- `Delete` 只是移到废纸篓，Service 不提供硬删除。
